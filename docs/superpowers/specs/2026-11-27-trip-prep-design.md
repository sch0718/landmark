# 여행 준비(예약·기초 정보·현지어 문장) 기획

- 상태: 기획 초안. 사용자 승인 전이라 코드는 고치지 않았다.
- 작성: 2026-11-27
- 전제: 사용자 1명(+함께 가는 사람)이 여러 기기에서 쓰는 개인 PWA. Cloudflare 무료, 앱 안에서 유료 API·LLM을 부르지 않는다. 판단이 갈리면 작은 쪽을 고른다.
- 첫 실사용: 이베리아 여행(2026-12-19 ~ 12-31, 파리·세비야·바르셀로나). 오늘부터 3주 남았다.

## 1. 요약

- 여행마다 `준비` 화면(`/trips/:id/prep`)을 하나 더 두고, 그 안에 **예약 · 정보 · 문장** 세 탭을 둔다.
- 저장은 여행(`Trip`) 문서의 **선택 필드 세 개**(`bookings`·`prepNotes`·`phrases`)로 한다. 새 항목 종류나 서버 테이블을 만들지 않는다. 그래서 동기화·백업·AI 편집(`yarn trip library put`)은 지금 장치를 그대로 탄다.
- 예약번호 같은 개인 정보는 **공유 링크·갱신 링크·함께 편집에 들어가지 않는다.** 공유 문서는 필드를 하나씩 골라 만들기 때문에, 새 필드는 따로 넣지 않는 한 빠진다.
- 내용은 주로 **사용자와 AI 도구가 채운다.** 앱이 외부 API(환율·날씨)를 직접 부를지는 사용자 결정으로 남긴다(§7). 추천은 「첫 버전에서는 부르지 않음」이다.
- 발음 듣기는 브라우저 내장 `speechSynthesis`를 쓴다. 번들이 늘지 않고 비용도 0이다. 기기에 그 언어의 음성이 없으면 구글 번역 링크로 대신한다.
- 첫 버전은 PR 두 개로 나눈다. ① 예약(저장 형식 포함), ② 정보·문장·발음. 둘 다 12월 19일 출발 전에 써 볼 수 있다.

## 2. 이미 있는 것과 겹치는 부분

| 필요 | 지금 있는 것 | 왜 그것으로는 안 되나 |
|---|---|---|
| 예약 현황 | Stop `note`(500자), 장소 `memo` | 상태·금액·기한을 모아 볼 수 없다. 항공·기차·여행자 보험처럼 장소가 아닌 예약은 붙일 곳이 없다. |
| 기초 정보 | 없음(여행 단위 메모가 없다) | 장소 메모는 장소 하나에 붙는다. 「스페인의 팁 문화」 같은 여행 전체 정보를 둘 곳이 없다. |
| 현지어 문장 | 없음 | 메모에 적을 수는 있지만 상황별로 고르거나 발음을 들을 수 없다. |
| 숙소에 보낼 메시지 | 없음 | 따로 만들지 않는다. 문장 탭의 「긴 문장」으로 둔다(§5.4). |

겹치지 않게 하는 원칙:

- **장소 하나에 대한 정보**(영업시간, 그 식당 메뉴 팁)는 지금처럼 장소 메모에 둔다. 준비 화면은 여행 전체에 걸친 것만 맡는다.
- **그날 일정의 메모**는 Stop `note`에 둔다. 예약 항목은 장소와 날짜로 이어 보일 뿐, 메모를 옮기지 않는다.

## 3. 고른 방식

| 방식 | 내용 | 판단 |
|---|---|---|
| A. 여행 메모 하나 | 여행에 긴 글 칸 하나만 더한다 | 가장 작지만 집계·필터·발음 듣기가 안 된다. 「한 곳에서 보기」라는 요청에 못 미친다. |
| **B. 여행 문서의 구조화된 선택 필드** | `Trip`에 `bookings`·`prepNotes`·`phrases`를 더한다 | **추천.** 동기화(필드 단위 LWW)·백업·AI 편집이 바로 동작한다. 서버 코드는 스키마 공유분 말고 바뀌지 않는다. |
| C. 새 항목 종류 `prep`(나라 단위) | 여러 여행이 나라 정보를 같이 쓴다 | 다시 쓸 수 있다는 장점이 있지만 서버·동기화·백업에 새 종류를 더해야 한다. 여행이 자주 있지 않은 1인 전제에서는 과하다. 「다른 여행에서 가져오기」(§8 나중에)로 대신한다. |

## 4. 저장 형식

### 4.1 `Trip`에 더할 선택 필드

기존 `legTransit`·`legMinutes`와 같은 방식이다. `Schema.optional(FieldSchema(...))`로 두어 옛 문서도 그대로 읽힌다. 동기화 병합은 최상위 필드 단위 LWW라서(`src/domain/library-sync/merge.ts` `mergeItem`) 필드 하나가 통째로 이기고 진다. 두 기기에서 같은 시간에 예약 목록을 고치면 늦은 쪽이 이기고, 진 값은 지금처럼 충돌 목록에 남는다. 1인이 쓰는 앱에서는 드문 일이라 항목 단위 병합은 만들지 않는다.

```ts
// src/schema/trip.ts (구현 때 한도는 LIBRARY_LIMITS로)
const BookingKind = Literals(['flight', 'train', 'bus', 'lodging', 'ticket', 'restaurant', 'tour', 'car', 'insurance', 'other']);
const BookingNeed = Literals(['required', 'recommended', 'optional']);
const BookingStatus = Literals(['todo', 'booked', 'pending', 'skipped']); // 예약 전·예약함·결제 대기·안 하기로 함

const Booking = Struct({
  id: 8자 영숫자,
  kind: BookingKind,
  title: String 1~80,                 // 「사그라다 파밀리아 입장권」
  need: BookingNeed,
  status: BookingStatus,
  date: NullOr(CalendarDate),          // 쓰는 날(일정의 어느 날인지)
  placeId: NullOr(PlaceId),            // 일정의 장소·숙소와 이을 때
  links: Array(Struct({ label: String 0~30, url: https URL 2000자 })) 0~5,
  bookBy: NullOr(CalendarDate),        // 이때까지 예약(매진 위험)
  at: NullOr(String "YYYY-MM-DDTHH:mm"), // 확정 일시(현지 시각, 시간대 없음)
  freeCancelUntil: NullOr(String "YYYY-MM-DDTHH:mm"),
  code: String 0~60,                   // 예약번호
  price: NullOr(Struct({ amount: Number ≥ 0, currency: 3자 대문자 })),
  bookedVia: String 0~40,              // 예약한 곳(사이트·앱)
  note: String 0~500,
});

const PrepNote = Struct({
  id: 8자,
  topic: Literals(['language', 'money', 'prices', 'weather', 'time', 'power', 'tips', 'safety', 'emergency', 'transit', 'docs', 'other']),
  region: String 0~30,                 // 「스페인」, 「파리」, 빈칸이면 여행 전체
  text: String 1~2000,
  sources: Array(https URL) 0~5,
  checkedOn: NullOr(CalendarDate),     // 확인한 날
  unsure: Boolean,                     // 「확인 필요」 표시
});

const Phrase = Struct({
  id: 8자,
  situation: Literals(['greet', 'restaurant', 'directions', 'transit', 'lodging', 'shopping', 'emergency', 'other']),
  ko: String 1~200,
  text: String 1~500,                  // 현지어
  lang: BCP 47 2~12자,                 // 「es-ES」, 「fr-FR」
  reading: String 0~300,               // 한글 읽는 법
  note: String 0~200,
});

TripSchema += {
  bookings: Schema.optional(FieldSchema(Array(Booking) 0~100)),
  prepNotes: Schema.optional(FieldSchema(Array(PrepNote) 0~60)),
  phrases: Schema.optional(FieldSchema(Array(Phrase) 0~200)),
};
```

- 관계 검증(`checkTrip`)에 더할 것: `placeId`가 보관함에 있는지(묘비 허용), 배열 안 `id` 중복. `date`는 검증하지 않는다. 여행 날짜를 옮겨도 저장이 깨지면 안 되기 때문이다. 기간 밖 날짜는 화면에서 「기간 밖」으로 표시한다.
- 크기: 최악일 때 여행 하나에 약 200KB가 더해진다. 보관함 상한(`libraryChars` 4,000,000)과 서버 상한(문서 5MB) 안이다.
- 금액은 통화별로 따로 더한다. 환율로 바꿔 한 숫자로 합치는 일은 첫 버전에서 하지 않는다.

### 4.2 동기화·백업·되돌리기

- `OPTIONAL_FIELD_EMPTY.trip`에 `bookings: []`, `prepNotes: []`, `phrases: []`를 더한다. 이렇게 해야 옛 기기가 이 필드를 빠뜨려 올려도 서버가 값을 남긴다(v0.37.1 규칙).
- `FIELDS_REFRESH`를 1 → 2로 올린다(선택 필드를 더할 때의 규칙).
- 계획 화면의 실행 취소(`src/domain/trips/undo.ts`)는 이 세 필드도 되돌리게 한다. 준비 화면에도 같은 실행 취소를 쓴다.
- 백업 파일은 보관함 전체를 담으므로 그대로 들어간다.
- **동기화를 켜면 예약번호·금액이 서버(D1)에도 저장된다.** 이미 장소 메모 등 보관함 전체가 올라가므로 새 종류의 저장은 아니다. 다만 개인정보 처리방침의 「저장 항목」에 「여행 준비(예약·메모)」를 한 줄 더한다.

### 4.3 옛 버전·롤백(`docs/rollback.md`)

- 옛 버전(이 기능 전)은 세 필드를 모르는 키로 보고 떼어 낸다. 보관함은 손상 화면 없이 열린다.
- 옛 버전에서 **그 여행을 고쳐 저장하면** 그 기기의 로컬 사본에서 세 필드가 사라진다. 동기화를 켜 두었다면 새 서버가 `keepMissingFields`로 값을 지킨다. 서버까지 되돌리면 값이 사라질 수 있다. 롤백 표의 마지막 칸에 `v0.37.0`과 같은 ⚠️를 적고, 되돌리기 전에 백업 파일을 받으라고 적는다.
- `schemaVersion`(2)은 바꾸지 않는다.

### 4.4 공유·갱신 링크·함께 편집

- 공유 v3·갱신 링크(`LiveTripDoc`)·함께 편집은 `ShareTripDoc`을 필드 하나씩 골라 만들고, `parseLiveDoc`은 키를 정확히 검사한다. 그래서 새 필드는 **따로 넣지 않는 한 나가지 않는다.** 이번 기능에서는 넣지 않는다.
- 함께 편집으로 받은 변경은 `src/domain/trip-collab/apply.ts`가 기존 여행을 펼쳐(`...trip`) 고치므로 새 필드가 남는다(확인함). 초대받은 사람 쪽에서 새로 만드는 여행은 빈 값으로 시작하므로 예약이 넘어가지 않는다. 앞의 경로를 지키는 시험을 하나 둔다.
- 함께 가는 사람에게 예약 내용을 보여 주는 일은 나중에 검토한다(§8). 보여 주더라도 예약번호는 빼고 상태·날짜·링크만 내보낸다.

### 4.5 AI 도구 연결

- AI는 이미 `yarn trip library get/put trip <id>`로 여행 문서를 고칠 수 있다(v0.32.0, `baseRev` 충돌 검사·되돌리기). 서버가 같은 `TripSchema`로 검사하므로, 이 기능을 배포하면 **CLI 코드를 바꾸지 않아도** AI가 세 필드를 채울 수 있다.
- 더할 것은 안내뿐이다. `yarn trip --help`의 `library` 절과 `docs/development.md`의 AI 절에 「준비 필드 예시 JSON」을 짧게 둔다. AI가 조사해 채울 때 `sources`·`checkedOn`·`unsure`를 꼭 쓰라고 적는다.
- `plan.json`(`yarn trip build`)은 공유 문서를 만드는 길이라 넓히지 않는다. 공유에는 준비 필드가 나가지 않기 때문이다.
- 이베리아 여행에서는 사용자가 만든 「이베리아 예약·준비장」의 예약 항목과 도시 정보를 AI가 `library put`으로 옮겨 담으면, 첫날부터 채워진 상태로 쓸 수 있다.

## 5. 화면과 흐름(휴대폰 기준)

### 5.1 들어가는 곳

- 계획 화면 제목 아래 단추 줄(`이름·기간 바꾸기`·`일정 공유` 옆)에 `준비`를 더한다. 아직인 필수 예약이 있으면 `준비 · 3`처럼 수를 붙인다.
- 여행 목록 카드에는 `예약 5/12`만 작게 보인다(필드가 있을 때만).
- 새 경로 `/trips/:id/prep`를 지연 로딩 페이지로 둔다(`src/routes/lazy-routes.ts`). 첫 화면 번들에는 아무것도 더하지 않는다.

### 5.2 예약 탭

```
┌ 이베리아 여행 · 준비 ───────────── ✕ ┐
│ [예약] [정보] [문장]                   │
│ ─────────────────────────────────── │
│ 예약함 7 / 12   ▓▓▓▓▓▓▓░░░░          │
│ 필수인데 아직 2 · 적은 금액 €612 ₩1,240,000 │
│                                       │
│ 지금 예약할 것                         │
│ ! 알람브라 입장권   ~12/01 · 필수   [열기] │
│ ! 사그라다 파밀리아 ~12/05 · 필수   [열기] │
│                                       │
│ (전체) (할 것만) (아직 안 한 것)       │
│ ── 12/19 (토) ───────────────────── │
│ ✈ 인천→파리  예약함 · 10:25 · AF267    │
│ 🏨 파리 숙소 예약함 · 무료 취소 12/15까지 │
│ ── 12/22 (화) ───────────────────── │
│ 🎫 루브르 입장권  예약 전 · 권장      │
│ ── 날짜 없음 ───────────────────── │
│ 🛡 여행자 보험   예약함                │
│                          [＋ 예약 더하기] │
└───────────────────────────────────────┘
```

- 「지금 예약할 것」: 상태가 `todo`·`pending`인 것 가운데 `bookBy`가 있는 것을 빠른 순으로 최대 5개 보인다. 필요도 `required`가 먼저, 기한이 지났으면 빨간 표시. `[열기]`는 첫 링크를 새 탭으로 연다.
- 목록은 `date` 순으로 묶고 `날짜 없음`을 맨 끝에 둔다. 필터 세 가지는 참고 아티팩트와 같다.
- 항목을 누르면 아래쪽 시트(기존 휴대폰 시트 패턴)로 편집한다. 칸 순서: 상태(네 칩) → 제목·종류·필요도 → 날짜·장소 고르기 → 링크들 → 확정 일시·예약번호·금액·예약한 곳 → 무료 취소 기한·이때까지 예약 → 메모. 예약번호에는 `복사` 단추를 둔다.
- 장소 고르기는 이 여행의 Stop·숙소 장소만 보인다(기존 `PlacePickerDialog` 재사용 검토).

### 5.3 정보 탭

```
│ [예약] [정보] [문장]                   │
│ (전체) (스페인) (프랑스)               │  ← region으로 거르기
│ 💶 돈·환율        스페인 · 11/27 확인   │
│   유로(EUR). 1€ ≈ 1,476원(11/26).     │
│   카드 결제 흔함, 소액은 현금…   [더 보기] │
│ 🌤 날씨           세비야 · ⚠ 확인 필요  │
│   12월 평균 최고 16° / 최저 6°…        │
│ 🔌 전압·플러그    여행 전체             │
│   230V, C·F형. 한국 플러그 그대로…      │
│ ☎ 긴급           스페인                 │
│   112. 주스페인 한국대사관 …   [출처 2] │
│                          [＋ 정보 더하기] │
```

- 주제(`topic`)마다 정해진 아이콘과 이름을 쓰고, 정해진 순서(언어 → 돈 → 물가 → 날씨 → 시간 → 전압 → 팁 → 치안 → 긴급 → 교통 → 서류 → 기타)로 보인다.
- 확인 날짜와 `⚠ 확인 필요`를 늘 보인다. 출처 링크는 접어 둔다.
- 본문은 줄바꿈만 살린 일반 글이다(마크다운을 해석하지 않는다).
- 첫 버전에서는 앱이 환율·날씨를 직접 조회하지 않는다(§7 결정 1).

### 5.4 문장 탭

```
│ [예약] [정보] [문장]                   │
│ (스페인어 es-ES) (프랑스어 fr-FR)      │
│ (인사)(식당)(길)(교통)(숙소)(쇼핑)(긴급)│
│ ── 식당 ─────────────────────────── │
│ 두 명 자리 있나요?                     │
│ ¿Tienen mesa para dos?                 │
│ 띠에넨 메사 빠라 도스      [▶] [🐢] [⋯] │
│ ─────────────────────────────────── │
│ 계산서 주세요.                          │
│ La cuenta, por favor.                  │
│ 라 꾸엔따, 뽀르 파보르     [▶] [🐢] [⋯] │
│                          [＋ 문장 더하기] │
```

- `▶` 보통 속도, `🐢` 느리게(rate 0.6) 읽는다. `⋯`에는 `크게 보기`(현지인에게 화면을 보여 줄 때 현지어만 큰 글씨), `복사`, `구글 번역에서 듣기`, `고치기`, `지우기`를 둔다.
- 숙소에 보낼 메시지 같은 긴 글도 문장 하나로 둔다(상황 `lodging`, 500자까지). `크게 보기`와 `복사`로 쓴다.
- 언어 칩은 이 여행의 문장에 들어 있는 `lang`만 보인다.

#### 발음 듣기(`speechSynthesis`)

- `speechSynthesis.getVoices()`에서 `lang`이 정확히 같은 음성을 먼저 고르고, 없으면 앞 두 글자(`es`)가 같은 음성을 고른다. 처음에 목록이 비어 있을 수 있어 `voiceschanged`를 한 번 기다린다(MDN 예제가 이 방식을 쓴다).
- 맞는 음성이 없으면 `▶` 대신 「이 기기에 스페인어 음성이 없어요」를 보이고, `구글 번역에서 듣기` 링크(`translate.google.com`, 문장을 주소에 담아 새 탭)로 대신한다. 이 링크는 사용자가 누를 때만 문장을 구글에 보낸다.
- 오프라인: `SpeechSynthesisVoice.localService`가 `true`인 음성은 기기 안 엔진이다. 오프라인에서도 될 가능성이 높지만, MDN은 「오프라인 가능」이라고 쓰지 않는다(§10 확인 필요). 실기기에서 비행기 모드로 확인한다.
- 이 부분은 의존성 없는 작은 모듈(`src/lib/speak.ts`, 약 80줄)로 두고, 음성 고르기 함수만 단위 시험한다.

#### 기본 문장 묶음

- 첫 버전은 **앱에 문장 묶음을 넣지 않는다.** 문장은 사용자가 더하거나 AI가 `library put`으로 채운다. 이유: 앱에 넣는 묶음도 결국 누군가 한 번 써야 하고, 한글 읽는 법의 정확도는 누가 쓰든 같다. 여행 단위로 채우면 그 여행 도시(예: 바르셀로나의 카탈루냐어 인사)에 맞출 수 있다.
- 기본 묶음을 앱에 넣을지는 §7 결정 3으로 남긴다. 넣는다면 언어별 JSON(약 30~40문장, 압축해 언어당 2~3KB)을 `import()`로 지연 로딩한다. `기본 문장 넣기`로 여행에 복사해 쓰는 방식이라 첫 화면 예산(`perf-budget.json`, 남은 여유 약 860B)에는 영향이 없다.

### 5.5 계획 화면·당일 모드와 잇기

- 계획 화면: `placeId`가 이어진 예약이 있으면 그 Stop·숙소 줄에 작은 배지(`🎫 예약함`, 아직이면 `🎫 예약 전`)를 단다. 누르면 준비 화면의 그 항목으로 간다.
- 당일 모드: 오늘 `date`인 예약을 맨 위 접힌 카드 `오늘 예약 2`로 보인다. 펼치면 확정 시각·예약번호(복사)·첫 링크가 있다. 공항·매표소에서 바로 꺼내 보기 위해서다.
- 이 둘은 첫 버전 두 번째 PR에 넣는다(§6). 예약 탭만으로도 쓸 수 있기 때문이다.

## 9. 시험과 확인

- 단위 시험
  - 스키마: 세 필드가 없는 옛 여행 문서를 읽는다. 한도(개수·글자 수)를 넘으면 거부한다. `checkTrip`이 없는 `placeId`·중복 `id`를 잡는다.
  - 동기화: 옛 클라이언트가 `bookings` 없이 올려도 서버 값이 남는다(기존 `sync-optional-fields` 시험 파일에 사례를 하나 더한다).
  - 집계: 예약 요약(예약함 n/전체, 필수인데 아직, 통화별 합계, 지금 예약할 것 순서)을 순수 함수로 시험한다.
  - `speak.ts`: 음성 고르기(정확히 일치 → 언어 앞부분 → 없음).
  - 함께 편집 적용이 준비 필드를 지우지 않는다(§4.4, `apply.ts`의 기존 시험 파일에 사례 하나).
- 화면 시험: 예약 하나 더하기 → 상태 바꾸기 → 집계 숫자가 바뀜. 컴포넌트 시험 하나로 한다(Playwright는 더하지 않음).
- 실기기 확인(사람): iPhone Safari·안드로이드 크롬에서 es-ES·fr-FR 문장 `▶`, 비행기 모드에서 `▶`, 음성이 없을 때 안내가 보이는지.
- 끝내기 전 `yarn build:ci`(첫 화면 예산 포함).
- **실제로 쓰는지 확인할 시점: 2027-01-10.** 이베리아 여행에서 예약 탭·문장 탭을 열어 봤는지 사용자에게 묻는다. 쓰지 않은 탭은 걷어내는 PR을 제안한다.

**확인 필요**

- iOS Safari에서 `speak()`에 사용자 동작(탭)이 필요한지. 버튼을 눌러 읽으므로 영향은 작다고 본다.
- 안드로이드 크롬의 `speechSynthesis`가 시스템 TTS 엔진을 쓰는지, 음성 데이터를 받아 두면 오프라인에서 되는지. 공식 문서에서 찾지 못했다. 실기기로 확인한다.
- iOS에서 사용자가 추가 음성을 받는 설정 경로. 안내 문구를 쓰기 전에 실기기로 확인한다.
- 카탈루냐어(ca-ES) 음성이 iOS·안드로이드에 있는지. 바르셀로나에서도 스페인어가 통하므로 첫 버전은 스페인어만 가정한다.
- Open-Meteo 요금 안내의 FAQ에는 「과거·기후 API는 Professional 이상」이라는 문장이 있고, 요금 표에는 무료로 되어 있어 서로 다르다. 결정 1에서 「다」를 고를 때만 다시 확인한다.
- 구글 번역 링크의 주소 형식(`?sl=auto&tl=es&text=…&op=translate`)은 공식 문서가 없다. 구현 때 실제로 열어 확인한다.
