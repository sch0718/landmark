# 공유 짧은 링크(`/s/<id>`) 설계

장소 내보내기·일정 공유의 링크를 카카오톡으로도 보낼 수 있게, 공유 문서를 서버(Cloudflare D1)에 맡기고 짧은 링크 `/s/<id>`를 만든다.
받는 사람이 짧은 링크를 열면 지금의 보기 화면 `/view#d=…`가 그대로 열린다.

이 문서는 **설계와 사용자 결정 항목까지만** 다룬다. 구현은 사용자가 [결정 항목](#사용자-결정-항목)을 정한 뒤에 한다.

## 배경

- 2026-10-27 `v0.19.0`~`v0.19.1`(#59, #62, #64)로 카카오톡 공유를 붙였다.
- 카카오 모바일 SDK는 보낼 메시지 JSON이 10,000자를 넘으면 오류를 내고 앱 밖 카카오 오류 화면으로 옮긴다. `webUrl`·`mobileWebUrl`을 같이 주면 링크가 메시지에 약 15번 들어가서, 링크는 400자까지만 보낼 수 있다(`KAKAO_LINK_MAX`, 운영 도메인에서 카카오 템플릿 검증으로 잰 값, 2026-10-27).
- 장소 1곳짜리 `/view#d=` 링크도 406자다. 그래서 장소·일정 공유 창에서는 카카오톡 단추가 늘 꺼지고(`링크가 길어 카카오톡으로 보낼 수 없어요…`) 짧은 약속 링크(`/meet/<id>`)만 카카오톡으로 간다.
- 링크의 `#해시`는 카카오 템플릿 안에서 그대로 남는 것을 확인했다(2026-10-27).

## 목표와 하지 않는 것

목표

- 장소 내보내기·일정 공유 창의 `카카오톡` 단추가 긴 링크 대신 짧은 링크로 동작한다.
- 받는 사람은 짧은 링크를 열면 지금과 같은 `/view#d=…` 보기 화면을 본다. 보기 화면과 공유 문서 형식(`ShareDoc` v1·v2)은 바꾸지 않는다.
- 서버에 맡기는 것은 사용자가 단추를 누를 때만 일어나고, 무엇이 얼마 동안 남는지 누르기 전에 보인다.

하지 않는 것

- 계정 로그인, 링크별 열람 횟수·열어 본 사람 기록.
- `/import#d=` 가져오기 링크의 짧은 판(보기 화면의 `Landmark에 담기`가 이미 같은 데이터로 가져온다).
- HTML 파일 공유를 서버로 옮기기.
- 32,000자를 넘는 문서를 짧은 링크로 보내기. 보기 화면이 받는 한도가 같으므로 지금처럼 파일로 보내게 한다.
- 예약 작업(Cron). 약속과 같이 만료 정리는 요청 때 한다.
- 새 외부 계정·키. D1(`DB`)·Turnstile(`VITE_TURNSTILE_SITE_KEY`·`TURNSTILE_SECRET`)·`IP_HASH_SALT`는 약속 온라인 집계가 쓰는 것을 그대로 쓴다.

## 사용 흐름

### 보내는 사람(장소 내보내기·일정 공유 창)

1. 지금처럼 제목·`메모 포함`을 고른다. `use-share-link`가 긴 링크를 미리 만든다(서버를 부르지 않는다).
2. 긴 링크가 400자 이하면 지금처럼 바로 보낸다(실제로는 거의 없다). 긴 링크가 `direct`이고 400자를 넘으면 `카카오톡` 단추를 켜고, 단추 아래에 보관 안내(§개인정보)를 보인다.
3. `카카오톡`을 누르면 단추가 `짧은 링크 만드는 중…`으로 바뀌고 서버에 올린다(Turnstile 확인 포함).
   올리기는 비동기라 같은 클릭에서는 카카오톡을 열 수 없다(PC 팝업 차단, 모바일의 사용자 동작 제약). 그래서 만들고 나면 단추가 `카카오톡으로 보내기`로 바뀌고, **한 번 더 누르면** `sendAppKakao`로 보낸다. 지금 약속의 `prepareKakaoLink`가 알림의 새 클릭에서 보내는 것과 같은 이유다(→ 결정 8).
4. 만든 짧은 링크는 창이 열려 있는 동안 (제목, 메모 포함, 문서 해시)별로 기억한다. 같은 입력으로 다시 누르면 다시 올리지 않는다. 제목·메모 포함을 바꾸면 새로 만들어야 한다.
5. `링크 복사`·`링크 공유`는 지금처럼 긴 링크를 쓴다(→ 결정 2).

### 받는 사람(`/s/<id>#k=<키>`)

1. 카카오톡 카드를 누르면 `/s/<id>`가 열린다.
2. 서버 함수가 작은 HTML(아래 "여는 쪽 페이지")을 돌려주고, 그 페이지가 문서를 풀어 `location.replace('/view#d=…')`로 보기 화면을 연다. 방문 기록에는 `/view#d=…`만 남는다.
3. 기한이 지났거나 지운 링크는 "링크 기한이 지났어요. 보낸 사람에게 다시 보내 달라고 해 주세요"를 보인다.

## 구조

### 링크 모양

```
https://landmark.sch0718.dev/s/<id>#k=<키>
```

- `<id>`: 서버가 만드는 16자 base64url(96비트 무작위). 메모가 들어갈 수 있으므로 넘겨짚을 수 없는 길이로 둔다. 약속 id(10자 `a-z0-9`)보다 길다.
- `#k=<키>`: 브라우저가 만든 AES-GCM 128비트 키(22자 base64url). 해시는 서버로 가지 않는다. 결정 1에서 평문 저장(안 A)을 고르면 `#k=`는 없다.
- 길이: 31 + 16 + 3 + 22 = **72자**. 카카오 메시지에서는 약 72 × 15 ≈ 1,080자라 한도 400자 안이다.

### 저장 값 — 결정 1

| | 안 A: 압축 해시 그대로 | 안 B: 브라우저에서 암호화(추천) |
|---|---|---|
| 서버가 받는 것 | `viewLink`가 만든 해시 값(`#d=` 뒤) | 같은 해시를 키 `k`로 AES-GCM 암호화한 값(IV 12바이트 + 암호문 + 태그 16바이트, base64url) |
| 서버·D1에서 읽을 수 있나 | 읽을 수 있다(장소 이름·주소·좌표·메모·일정) | 읽을 수 없다. 키는 링크의 해시에만 있다 |
| `/s/<id>` 응답 | `302 Location: /view#d=<해시>` | 암호문을 넣은 작은 HTML. 페이지가 키로 풀고 `location.replace` |
| 보기 화면 변경 | 없음 | 없음 |
| 앱 변경 | 올리기 호출 | 올리기 호출 + WebCrypto 암호화(수십 줄) |
| 서버 변경 | 함수·표 | 함수·표 + 여는 쪽 페이지(인라인 스크립트 하나) |
| 해시가 잘리는 메신저 | 상관없음 | 링크가 열리지 않는다(카카오톡은 해시가 남는 것을 확인했다) |
| 확인 필요 | 3xx `Location`에 32,000자 넘는 값을 Cloudflare가 넘기는지(구현 전에 미리보기 배포에서 잰다) | 카카오톡 인앱 브라우저의 `crypto.subtle`·`location.replace`(실기기) |

안 B를 추천한다. 메모를 쓰는 사용자에게 "서버에는 읽을 수 없는 사본만 남아요"라고 말할 수 있고, D1이 새거나 운영자가 표를 봐도 내용이 나오지 않는다. 늘어나는 코드는 앱 쪽 암호화 하나와 여는 쪽 페이지 하나이며, 보기 화면은 그대로다.

### 서버 API

진입점은 `functions/api/share/*`·`functions/s/[id].ts`, 처리 코드는 `src/server/share/*`에 둔다. `src/server/meet/*`의 `MeetDb`·`ensureSchema`·`consumeLimit`·`hashIp`·`hashToken`·`verifyTurnstile`을 같이 쓴다.

| 요청 | 하는 일·성공 응답 | 권한·검사 |
|---|---|---|
| `POST /api/share` | `{ body, kind, keepUntil, turnstile, deleteToken }` → `201 { id, expiresAt }`. `deleteToken`(43자 base64url)은 브라우저가 먼저 만든다. 응답이 사라져 같은 토큰으로 다시 보내면 같은 `id`로 `200`(약속 `hostToken`과 같은 방식) | 출처·본문 크기·Turnstile·일 한도·`SHARE_SHORT` 스위치 |
| `GET /s/:id` | 안 B: `200` 여는 쪽 HTML. 안 A: `302 Location: /view#d=…` | 없음(링크 소지자). 출처 검사를 **하지 않는다**: 카카오톡에서 연 화면 이동에는 `Origin`·`Referer`가 없다 |
| `DELETE /api/share/:id` | `Authorization: Bearer <deleteToken>` → `204` | 출처·삭제 토큰 |

- `body`: 안 B면 `^[A-Za-z0-9_-]{1,32100}$`(32,000자 해시 + IV·태그), 안 A면 `^[A-Za-z0-9_-]{1,32000}$`. 서버는 내용을 풀어 보지 않는다(안 B는 풀 수 없고, 안 A도 5MB까지 풀리는 문서의 검사는 함수 CPU 시간이 부담된다). 문서 검사는 지금처럼 보기 화면이 한다.
- 본문을 읽기 전에 `Content-Length`가 40,000바이트를 넘으면 `413`으로 끊는다.
- `kind`: `places` | `trip`. 보관 기간 계산과 집계에만 쓴다.
- `keepUntil`: 브라우저가 계산한 날짜(결정 3). 서버는 `[지금 + 30일, 지금 + 최대 기간]`으로 자른다.
- 모든 응답은 `Cache-Control: private, no-store`. `GET /s/:id` HTML은 `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex`도 직접 붙인다(`public/_headers`는 정적 파일에만 붙는다).
- 오류는 `src/server/http.ts`의 `ApiError` 형식을 따른다. `GET /s/:id`만 JSON 대신 사람이 읽는 HTML(404·410·503)을 돌려준다.

### D1 표

`src/server/meet/schema-sql.ts`의 `SCHEMA_STATEMENTS`에 추가형으로 더하고 `SCHEMA_VERSION`을 2로 올린다. `ensureSchema`가 첫 요청에서 `CREATE TABLE IF NOT EXISTS`를 실행한다. 수동 SQL은 필요 없다.

```sql
CREATE TABLE IF NOT EXISTS share_links (
  id TEXT PRIMARY KEY,          -- 16자 base64url
  body TEXT NOT NULL,           -- 안 B: 암호문, 안 A: 압축 해시
  kind TEXT NOT NULL,           -- 'places' | 'trip'
  delete_hash TEXT NOT NULL,    -- 삭제 토큰의 SHA-256(원문은 두지 않는다)
  created_at TEXT NOT NULL,
  expires_at TEXT NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS share_links_delete ON share_links(delete_hash);
CREATE INDEX IF NOT EXISTS share_links_expires ON share_links(expires_at);
```

- id가 겹치면(`UNIQUE constraint failed: share_links.id`) 새 id로 최대 3번 다시 넣는다.
- 같은 `delete_hash`로 다시 오면 기존 행의 `id`·`expires_at`을 돌려준다(본문은 처음 것을 둔다).
- 만료 정리: `POST`와 `GET /s/:id` 때 `waitUntil`로 만료 행을 최대 20개 지운다. 읽기만 있는 날에도 정리되게 GET에서도 한다.

### 여는 쪽 페이지(안 B)

서버 함수가 아래 모양의 HTML을 만든다. 보기 화면 번들을 쓰지 않는 수십 줄짜리 페이지다.

```html
<!doctype html><meta charset="utf-8"><meta name="viewport" content="width=device-width">
<title>Landmark</title>
<script type="application/json" id="c">"<암호문 base64url>"</script>
<script>/* #k를 읽어 AES-GCM으로 풀고 location.replace('/view#d=' + 해시). 실패하면 안내 문구 */</script>
<noscript>이 링크는 JavaScript가 필요해요.</noscript>
<p id="m">여는 중…</p>
```

- `Content-Security-Policy: default-src 'none'; script-src 'sha256-<인라인 스크립트 해시>'; style-src 'unsafe-inline'`. 암호문은 base64url 글자만이라 HTML에 그대로 넣어도 깨지지 않는다(데이터 블록은 실행되지 않는다).
- 키가 없거나(`#k=`가 잘림) 풀기에 실패하면 "링크가 온전하지 않아요. 보낸 사람에게 링크를 다시 받아 주세요". `crypto.subtle`이 없으면 "이 브라우저에서는 열 수 없어요. 다른 브라우저로 열어 주세요".
- 푼 값은 앱의 `viewLink`와 같은 해시 문자열이라 보기 화면이 지금과 똑같이 검사·표시한다.

### 앱 쪽

- `src/share-viewer/encode.ts`(또는 새 `src/services/share-short/`): `encryptShareHash(hash) → { body, key }`(안 B), `shortLink(id, key, app)`.
- `src/services/share-short/client.ts`: `POST /api/share`·`DELETE`, Turnstile은 `src/services/meet-online/turnstile-loader.ts`를 같이 쓴다(약속과 같은 사이트 키).
- `ShareFileDialog.tsx`: 카카오톡 단추 상태 `idle → creating → ready → (보냄)`, 실패 문구, 보관 안내. `linkDoc`이 있는 두 창(장소 내보내기·일정 공유)에 함께 적용된다.
- 기기 저장 `tripmap:share-links:v1`: `{ id, deleteToken, title, kind, createdAt, expiresAt }[]`(최대 100개, 만료된 것은 읽을 때 지움). **키 `k`는 저장하지 않는다.** 철회(결정 4)에 쓴다. 백업 파일에는 넣지 않는다.

## 보관 기간과 철회 — 결정 3·4

- 보관 기간은 결정 3을 따른다. 추천은 **장소 30일, 일정은 여행 마지막 날 + 7일과 30일 중 늦은 쪽(최대 180일)**이다. 일정은 몇 달 전에 보내고 여행 당일에 다시 여는 일이 많아 30일 고정이면 여행 전에 끊길 수 있다. 장소는 약속(30일)과 맞춘다.
- 기한이 지난 링크는 `410` 안내를 보이고, 만료 정리가 돌면 행을 지운다.
- 철회: 보낸 기기는 삭제 토큰으로 `DELETE /api/share/:id`를 부를 수 있다. 화면은 결정 4를 따른다. 추천은 **설정 › `보낸 짧은 링크`** 목록(제목·종류·만든 날·기한, `지우기`)이다.
- 다른 기기에서는 지울 수 없다(토큰은 만든 기기에만 있다). 기한이 지나면 지워진다.
- 받은 사람이 이미 `Landmark에 담기`로 가져간 것과 `/view#d=…` 방문 기록은 철회로 지워지지 않는다. 안내에 적는다.

## 개인정보 — 결정 1·7

### 서버에 남는 것

| 무엇 | 안 A | 안 B | 얼마 동안 |
|---|---|---|---|
| 공유 문서(제목, 장소 이름·주소·좌표·라벨, 메모 포함 시 메모, 일정의 Day·시간·구간) | 읽을 수 있는 압축 해시 | 읽을 수 없는 암호문 | 결정 3의 기한, 또는 철회 때까지 |
| 삭제 토큰 | SHA-256 해시만 | 같음 | 행과 함께 |
| IP | 소금 친 해시가 일 한도 카운터 키에만 | 같음 | 다음 날 정리(`pruneLimits`) |
| 키 `k` | — | 서버에 가지 않는다 | — |

- 카카오톡 메시지에는 링크 전체(`#k=` 포함)가 들어간다. 카카오는 지금도 긴 링크를 보내면 문서 전체를 받는 셈이라 새로 생기는 노출은 아니다.
- Cloudflare 요청 기록에는 경로 `/s/<id>`만 남고 해시는 남지 않는다.

### 안내 문구(안)

공유 창의 `카카오톡` 단추 아래, 단추를 누르기 **전에** 보인다.

- 안 B: `카카오톡으로 보내면 짧은 링크를 위해 암호화한 사본을 Landmark 서버에 {기한}까지 보관해요. 링크를 받은 사람은 누구나 볼 수 있어요`
- 안 A: `카카오톡으로 보내면 짧은 링크를 위해 사본을 Landmark 서버에 {기한}까지 보관해요. 링크를 받은 사람은 누구나 볼 수 있어요`
- 메모 포함이면 기존 `링크를 받은 사람은 누구나 메모를 볼 수 있어요`를 그대로 둔다(결정 7에서 메모를 빼기로 하면 `카카오톡 링크에는 메모를 넣지 않아요`로 바꾼다).
- 만든 뒤: `짧은 링크를 만들었어요({기한}까지). 설정 › 보낸 짧은 링크에서 지울 수 있어요`

`{기한}`은 `11월 27일`처럼 날짜로 보인다.

함께 고칠 문서: `docs/development.md`의 링크 공유·개인정보 문단("서버에 저장하지 않습니다"), 앱 도움말 `share` 쪽(`src/sections/help/help-content.ts`), README의 개인정보 줄(로그인 없이 쓰며… 서버에 사본을 올려)에 짧은 링크를 더한다.

## 크기·요청 한도와 Turnstile — 결정 5·6

| 항목 | 값 | 이유 |
|---|---|---|
| 본문 | 해시 32,000자(안 B는 IV·태그 포함 32,100자), 요청 40,000바이트 | 보기 화면이 받는 한도(`MAX_HASH_CHARS`, `SHARE_IMPORT_LIMITS.hashChars`)와 같다. 넘는 문서는 이미 `too-big`이라 짧은 링크도 만들지 않는다 |
| 만들기 | IP 해시당 하루 50번(결정 6) | 약속 올리기(20)보다 자주 쓴다. 최악일 때 IP 하나가 하루 약 1.6MB를 쓴다 |
| 지우기 | IP 해시당 하루 200번 | 목록 정리 |
| 읽기 | 없는 링크(`404`)·만료(`410`)만 IP 해시당 하루 5,000번 | 약속 읽기와 같은 규칙. 정상 읽기는 카운터를 쓰지 않는다. id 넘겨짚기를 늦춘다 |
| Turnstile | 만들기에 사용(결정 5), 약속과 같은 보이지 않는 위젯 | 서버가 내용을 검사하지 않는 32KB 보관소라, IP를 바꿔 가며 채우는 남용을 막는다. 새 키는 필요 없다 |

`LIMITS`에 `shareCreate`·`shareDelete`·`shareRead`를 더해 약속 카운터와 섞이지 않게 한다. D1 무료 사용량(저장 용량·하루 쓰기 행)은 구현 전에 Cloudflare 문서에서 다시 확인해 날짜와 함께 `docs/development.md`에 적는다.

## 어떤 단추가 짧은 링크를 쓰나 — 결정 2

추천: **카카오톡 단추만**.

- `링크 복사`·`링크 공유`의 긴 링크는 서버 없이 열리고, 서버 장애·기한·철회와 상관없다. 이 장점을 그대로 둔다.
- 짧은 링크가 필요한 곳은 링크 길이 한도가 있는 카카오톡뿐이다. 다른 메신저는 긴 링크를 받는다.
- 서버에 맡기는 일을 사용자가 카카오톡을 고를 때로 좁히면 안내도 그 단추 옆에만 두면 된다.

## 오프라인·서버 장애

| 상황 | 보내는 쪽 | 받는 쪽 |
|---|---|---|
| 오프라인 | 카카오톡 단추는 켜 두고, 누르면 `인터넷 연결을 확인해 주세요. 링크 복사를 이용해 주세요` | — |
| Turnstile을 불러오지 못함 | `확인 도구를 불러오지 못했어요. 링크 복사를 이용해 주세요` | — |
| `429` | `오늘 만들 수 있는 짧은 링크를 다 썼어요. 링크 복사를 이용해 주세요` | 없는 링크를 너무 많이 열면 `잠시 뒤 다시 열어 주세요` |
| `503`(`SHARE_SHORT=off`) | 지금처럼 `링크가 길어 카카오톡으로 보낼 수 없어요. 링크 복사를 이용해 주세요` | 이미 만든 링크 읽기는 스위치와 상관없이 계속 된다 |
| `503`(설정 누락)·`5xx` | `짧은 링크를 만들지 못했어요. 링크 복사를 이용해 주세요` | `잠시 뒤 다시 열어 주세요. 계속 안 되면 보낸 사람에게 다른 방법으로 보내 달라고 해 주세요` |
| D1 장애 중 이미 보낸 링크 | — | 위와 같음. 데이터가 서버에만 있으므로 받는 쪽에서 다른 대체 방법은 없다. 결정 2에서 긴 링크를 남기는 이유다 |

- 기능 스위치 `SHARE_SHORT=off`(Pages 환경 변수)는 새로 만들기만 멈춘다. `MEET_ONLINE`과 따로 둔다.
- 앱은 `503 reason: 'off'`를 받으면 그 창에서는 카카오톡 단추를 다시 지금처럼 끈다.

## 롤백 영향(`docs/rollback.md`)

이 기능을 `v0.20.0`으로 낸다고 할 때, 그보다 옛 배포·코드로 되돌리면:

- `functions/s/[id].ts`가 사라져 `/s/<id>`는 SPA 기본 동작으로 앱 화면이 열리고 `페이지를 찾을 수 없어요`가 된다. 이미 보낸 카카오톡 링크는 그동안 열리지 않는다.
- D1의 `share_links` 행은 지우지 않는다. 다시 새 버전으로 오면 기한이 남은 링크는 그대로 열린다.
- `schema_meta`는 2로 남는다. 옛 코드의 `ensureSchema`는 `version >= 1`이면 아무것도 하지 않으므로 약속은 그대로 동작한다.
- 옛 코드에는 만료 정리가 없어, 되돌린 동안 기한이 지난 행이 D1에 남는다(읽히지는 않는다). 오래 되돌려 둘 때는 `wrangler d1 execute landmark --remote --command "DELETE FROM share_links WHERE expires_at <= strftime('%Y-%m-%dT%H:%M:%fZ','now')"`로 지운다.
- 기기 키 `tripmap:share-links:v1`은 옛 버전이 읽지도 지우지도 않는다. 보관함·백업·공유 문서 형식은 바뀌지 않는다.
- 서버 쪽 문제만 피하려면 되돌리기 대신 `SHARE_SHORT=off`를 넣고 다시 배포한다.
- 코드 되돌리기 순서: 이 PR이 `src/server/meet/schema-sql.ts`·`limits.ts`·`ShareFileDialog.tsx`·`kakao.ts`를 고치므로, 앞 PR(#55·#59·#62)을 되돌리려면 이 PR을 먼저 되돌린다. 표에 줄을 더한다.
