# 랜드마크 설계 — 네이버 폴더 다시 가져오기 (묶음 F3)

- 작성일: 2026-10-16
- 상태: 초안 (사용자 검토 대기)
- 태그: `v0.10.0` (F1 `v0.8.0`·F2 `v0.9.0` 다음)
- 관련 문서: `2026-10-12-place-adding-design.md` §2.3·§3.5(폴더 가져오기), `2026-10-08-place-library-design.md` §3(데이터 모델), `docs/rollback.md`. 충돌하면 이 문서가 우선한다.
- 묶음 사이 약속: **C5 폴더 기록의 주인**이다(§5).

## 1. 배경과 목표

### 1.1 지금 있는 것

- ＋ → `네이버 폴더 가져오기` → 공유 링크를 붙여 넣으면 `/api/place`가 폴더로 풀고(`FolderRef`), 추가 칸의 `folder` 단계(`FolderPreview`)가 `/api/naver-folder?share=<공유 ID>`로 폴더를 읽어 미리보기(`FolderList`)를 보인다. 가져오면 `importFolder`가 한 라벨로 넣는다. 이미 있는 곳은 라벨만 더하고, 지운 곳은 되살린다.
- 가져온 뒤에는 **어느 폴더를 가져왔는지 남지 않는다.** 다시 하려면 링크를 다시 찾아 붙여 넣어야 하고, 미리보기는 폴더 전체를 다시 보여 준다(모두 체크, 대부분 `이미 있음`).
- 서버는 폴더 결과를 엣지 캐시에 **10분** 둔다(`functions/api/naver-folder.ts`). 경로(`/api/route`)에만 캐시를 건너뛰는 `fresh=1`이 있다.
- 2026-10의 새 공유 링크는 `/v5/favorite/myPlace/folder/<ID>`로 이동한다(PR #14, `v0.7.1`). `src/server/links.ts`는 옛 `/p/favorite/sharedPlace/folder/<ID>`와 같이 그 ID를 공유 ID로 본다.

### 1.2 확인한 사실 (2026-10-16)

공개 폴더 API를 한 번 불렀다(`shares/fb65e7f93f8a4144a4ded594d604a7aa/bookmarks?start=0&limit=500`, 200).

- 최상위: `folder`, `bookmarkList`, `unavailableCount`, `mismatchedCount`, `removed`.
- `folder`: `name`, `shareId`, `bookmarkCount`(31), `creationTime`, `lastUseTime`(ms) 등.
- 북마크마다 `sid`, `name`, `address`, `px`, `py`, `memo`, `available`, 그리고 **`creationTime`·`lastUpdateTime`·`useTime`(ms)** 가 있다. 이 폴더는 31곳, 모두 `type: 'place'`·`available: true`. CLAUDE.md의 15곳보다 늘었다 — 사용자가 계속 저장한다는 근거다.
- 없는 공유 ID는 `400` + `apiErrorCode 1603 "공유 정보가 존재하지 않습니다."`. 서버는 이것을 `NOT_FOUND`로 바꾼다(`resolveFolder`의 `notFoundStatuses: [400, 404]`).
- 확인 못 함: 폴더 공유를 끄거나 폴더를 비공개로 바꿨을 때의 응답(같은 1603인지), 공유를 껐다 다시 켜면 공유 ID가 바뀌는지, 북마크를 다른 폴더로 옮기면 `creationTime`이 남는지. 이 설계는 셋 중 어느 것에도 기대지 않는다(§3.2·§6).

### 1.3 목표

한 번 가져온 네이버 폴더를 기억해 두고, 버튼 하나로 다시 읽어 **그사이 새로 저장한 곳만** 더한다.

1. 폴더를 가져오면 공유 ID·폴더 이름·붙인 라벨·본 장소·확인한 시각을 보관함 문서에 남긴다.
2. 라벨 관리에서(또는 같은 링크를 다시 붙여 넣어) 다시 가져오기를 연다. 미리보기는 **새로 저장한 곳 N · 그대로 M · 폴더에서 빠진 곳 K**로 나눠 보인다.
3. 폴더에서 빠진 곳은 **지우지 않고 알리기만** 한다. 보관함에서 지운 곳은 **되살리지 않지만** 골라서 되살릴 수 있다.

구글·네이버와 다른 점: 네이버 저장 폴더는 계속 쌓이는 원본이고, 랜드마크는 그 위에 라벨·메모·여행을 얹은 **내 정리본**이다. 다시 가져와도 내가 고친 것(지운 장소, 뗀 라벨, 메모)을 덮지 않는다.

### 1.4 성공 기준

- 폴더를 처음 가져온 뒤 네이버에 2곳을 더 저장하고 다시 가져오기를 누르면, 미리보기에 그 2곳만 체크되어 보이고 `2곳 가져오기` 한 번으로 같은 라벨에 들어간다.
- 지난번에 가져왔다가 보관함에서 지운 곳, 장소에서 뗀 폴더 라벨은 다시 가져오기로 되돌아오지 않는다(직접 고르면 되살린다).
- 네이버에 방금 저장한 곳이 10분 캐시 때문에 안 보이는 일이 없다.
- 공유가 꺼진 폴더는 오류 문구와 `연결 끊기`를 보인다. 장소·라벨은 그대로다.
- `v0.9.x` 이하로 되돌려도 손상 화면이 뜨지 않는다(§5.3).

## 2. 범위

**한다**

- 보관함 문서에 폴더 연결(`folders`) 선택 컬렉션(§5).
- 첫 가져오기(지금 흐름)가 연결을 남긴다. 같은 폴더를 다시 가져오면 연결을 새로 쓴다.
- 다시 가져오기 미리보기(`FolderResync`)와 연결 끊기.
- 진입: 라벨 관리의 라벨 고치기 대화상자, 같은 링크 붙여 넣기.
- 다시 가져오기는 서버 캐시를 건너뛴다(`fresh=1`).
- 라벨을 지우면 그 라벨의 연결도 끊고, 라벨을 합치면 연결을 합친 라벨로 옮긴다.

**안 한다**

- 여러 폴더를 한 번에 다시 가져오기(§12 결정 7). 이번에는 한 폴더씩.
- 자동·주기적 다시 가져오기(앱이 열릴 때 등). 서버 동기화가 없고, 사용자가 누를 때만 읽는다.
- 폴더에서 빠진 곳의 라벨 떼기·장소 지우기(§12 결정 3).
- 바뀐 이름·주소·좌표·네이버 메모를 기존 장소에 덮어쓰기. 지금 가져오기처럼 이미 있는 장소는 라벨만 다룬다.
- 내 폴더(공유하지 않은 폴더) 읽기. 공개 공유 API만 쓴다.
- 서버의 폴더 응답 모양 바꾸기(`FolderResult` 그대로). 북마크 시각 필드는 쓰지 않는다(§3.2).

## 3. 다시 가져오기의 규칙

### 3.1 폴더 연결 하나에 남기는 것

| 값 | 뜻 |
|---|---|
| 공유 ID | 연결의 키. `/p/…/sharedPlace/folder/<ID>`·`/v5/…/myPlace/folder/<ID>` 어느 링크로 왔든 같은 ID다 |
| 폴더 이름 | 마지막으로 읽었을 때 네이버 폴더 이름(앞뒤 공백 제거, 100자까지 자름). 라벨 이름과 따로 둔다 |
| 라벨 | 가져올 때 붙인 라벨 |
| 본 장소 | 마지막으로 읽었을 때 폴더에 있던 장소 `sid` 전부(가져오기에서 고르지 않은 곳도 포함, 최대 1,000개) |
| 확인한 시각 | 마지막으로 가져오기·`확인했어요`를 누른 시각 |

### 3.2 무엇이 "새로 저장한 곳"인가

폴더의 장소(같은 `sid`는 처음 것만, `uniqueBySid`)를 **본 장소**와 보관함으로 나눈다.

| 분류 | 조건 | 미리보기 | 가져오면 |
|---|---|---|---|
| **새로 저장한 곳** | 본 장소에 없음 | 체크된 채로 보임. 보관함에 살아 있으면 `이미 있음`, 지운 것만 있으면 `지웠던 곳` 표시 | 없으면 새로 만들고(네이버 메모 포함), 있으면 라벨만 더하고, 지운 것은 되살린다(`importFolder`와 같음) |
| **보관함에서 지운 곳** | 본 장소에 있고, 보관함에는 지운 장소만 있음 | 따로 묶어 **체크 없이** 보임 | 고른 것만 되살리고 라벨을 붙인다 |
| **그대로** | 본 장소에 있고 위가 아님 | 개수만 | 건드리지 않는다(뗀 라벨을 다시 붙이지 않는다) |
| **폴더에서 빠진 곳** | 본 장소에 있었는데 지금 폴더에 없고, 보관함에 살아 있음 | 이름·주소 목록(체크 없음) | 건드리지 않는다 |

- 판단 기준을 네이버의 `creationTime` 대신 **본 장소 목록**으로 둔다. 북마크를 다른 폴더로 옮겼을 때의 시각 규칙을 확인하지 못했고, 기기 시계와도 상관이 없게 하려는 것이다(§12 결정 2).
- 가져오기를 누르면 **본 장소를 지금 폴더의 장소 전부로 바꾼다.** 이번에 고르지 않은 새 곳도 "본 것"이 되어 다음에는 `그대로`로 센다(§12 결정 8). 다시 넣고 싶으면 `폴더 전체 보기`(§4.3)로 지금 가져오기 화면을 연다.
- 빠졌던 곳을 네이버에 다시 저장하면 본 장소에 없으므로 다음에 `새로 저장한 곳`으로 나온다.

### 3.3 첫 가져오기와 옛 가져오기

- 지금의 폴더 가져오기(`FolderList`)도 가져오기를 누르면 연결을 남긴다. 본 장소는 폴더의 장소 전부(체크를 푼 곳 포함).
- 같은 공유 ID의 연결이 이미 있으면(지운 연결 포함) 새로 쓴다: 라벨·이름·본 장소·확인한 시각을 이번 값으로, 처음 만든 시각은 그대로.
- `v0.10.0` 전에 가져온 폴더에는 연결이 없다. 같은 링크를 한 번 더 붙여 넣으면 지금 가져오기 화면이 열리고(연결이 없으므로), 라벨 이름이 폴더 이름과 같아 기존 라벨을 다시 쓰며(정규형 비교), 대부분 `이미 있음`이다. 가져오면 연결이 생긴다. 따로 옮겨 오는 화면은 두지 않는다.

### 3.4 라벨이 바뀌면

- **라벨 지우기**: 그 라벨에 붙은 살아 있는 연결을 함께 지운다(`deletedAt`). 장소는 지금처럼 남는다.
- **라벨 합치기**: 옮겨 가는 라벨(`from`)의 연결을 합친 라벨(`into`)로 옮긴다.
- 이름·색·아이콘 바꾸기는 연결과 상관없다. 폴더 이름이 네이버에서 바뀌어도 라벨 이름은 그대로 둔다.
- 불변식: 살아 있는 연결은 살아 있는 라벨을 가리킨다(§5.2). 라벨 연산이 위 두 규칙으로 지킨다.

## 4. 화면

### 4.1 들어오는 길

1. **라벨 관리**(`/labels`): 연결이 있는 라벨 줄의 개수 글자가 `장소 <N>곳 · 네이버 폴더`가 된다. 줄을 눌러 여는 `라벨 고치기` 대화상자에 **`네이버 폴더`** 구역이 생긴다(§4.2). 거기서 `새로 저장한 곳 가져오기`를 누르면 대화상자를 닫고 추가 칸에 다시 가져오기를 연다.
2. **같은 링크 붙여 넣기**: ＋ → `네이버 폴더 가져오기`(또는 `링크 붙여넣기`)에 연결된 폴더의 링크를 넣으면, 폴더를 읽은 뒤 지금 가져오기 대신 다시 가져오기 화면을 보인다. 단, 여행 계획 화면에서 연 흐름(여행 대상이 붙은 흐름)은 지금처럼 폴더 전체 미리보기다(그 여행의 후보에 넣으려는 것이므로).
3. 보관함 라벨 칩·설정에는 두지 않는다(§12 결정 5).

화면 자리는 지금 폴더 미리보기와 같다.

- 좁음(<768): 아래 시트(높이 90vh, `folder` 단계 그대로).
- 중간(768~1279)·넓음(≥1280): `/labels`에서는 본문 위에 뜨는 오른쪽 칸(`AddPlaceHost floating`, 너비 `DETAIL_WIDTH`). 보관함(`/`, `/map`)에서 링크로 열면 지금처럼 넓음은 오른쪽 칸, 중간은 뜨는 칸.
- 칸을 닫으면 포커스는 그 칸을 연 요소로 돌아간다. 라벨 관리에서 열었으면 그 라벨 줄, ＋로 열었으면 ＋.

### 4.2 라벨 고치기 대화상자의 `네이버 폴더` 구역

색·아이콘 고르기 아래, 단추 줄 위. 연결이 없는 라벨에는 구역이 없다.

```
네이버 폴더                                   (h3)
속초, 고성, 양양 맛집
2026.10.12 확인
[새로 저장한 곳 가져오기]  [연결 끊기]
```

- 폴더 이름이 비면 `이름 없는 폴더`. 날짜는 확인한 시각의 로컬 날짜 `YYYY.MM.DD`.
- 한 라벨에 연결이 여럿이면 폴더 이름순으로 줄마다 같은 모양.
- 단추의 접근 이름: `‘<폴더 이름>’에서 새로 저장한 곳 가져오기`, `‘<폴더 이름>’ 연결 끊기`(보이는 글자를 포함한다).
- `연결 끊기`는 바로 끊고 토스트 `폴더 연결을 끊었어요. 라벨과 장소는 그대로예요`. 되돌리기는 같은 링크를 다시 붙여 넣으면 된다.
- 라벨 지우기 확인 문구: 연결이 있으면 지금 문장 뒤에 ` 연결된 네이버 폴더도 끊겨요.`를 붙인다.

### 4.3 다시 가져오기 미리보기 (`FolderResync`)

```
속초, 고성, 양양 맛집                           (h2)
‘속초, 고성, 양양 맛집’ 라벨 · 지난 확인 2026.10.12
새로 저장한 곳 2 · 그대로 28 · 폴더에서 빠진 곳 1

새로 저장한 곳                       [전체 해제]   (h3)
☑ 스튜디오 토성당     강원 고성군 …
☑ 델피노 더엠브로시아 강원 고성군 …     [이미 있음]

보관함에서 지운 곳                                  (h3, 있을 때만)
전에 가져왔다가 보관함에서 지운 곳이에요. 다시 넣으려면 고르세요
☐ 코끼리분식          강원 속초시 …

폴더에서 빠진 곳                                    (h3, 있을 때만)
네이버 폴더에서는 빠졌지만 보관함에서는 지우지 않았어요
  타이그랜파          강원 속초시 …

──────────────────────────────────────
[폴더 전체 보기]                 [취소] [2곳 가져오기]
```

- 머리 줄: 제목은 지금 읽은 폴더 이름(비면 `이름 없는 폴더`). 둘째 줄 `‘<라벨 이름>’ 라벨 · 지난 확인 <YYYY.MM.DD>`. 셋째 줄 `새로 저장한 곳 <N> · 그대로 <M> · 폴더에서 빠진 곳 <K>`(0도 쓴다).
- `새로 저장한 곳`이 0곳이면 목록 대신 `<YYYY.MM.DD> 뒤로 새로 저장한 곳이 없어요`. 전체 선택 단추는 없다.
- 행 모양·체크박스·표시 글자(`이미 있음`)는 지금 폴더 미리보기(`FolderPlaceRows`)와 같다. 새 표시 글자 `지웠던 곳`.
- 전체 선택 단추는 `새로 저장한 곳` 목록에만 있다(`전체 선택`/`전체 해제`). `보관함에서 지운 곳`은 줄마다 고른다.
- 주 단추: 고른 수(새로 저장한 곳 + 지운 곳에서 고른 것)가 1 이상이면 `<N>곳 가져오기`, 0이면 `확인했어요`. 둘 다 누르면 §3.2대로 본 장소·확인한 시각을 새로 쓴다. 누르는 사이 두 번 눌러도 한 번만 한다(지금 `savingRef`와 같은 방식).
- `폴더 전체 보기`(글자 단추): 같은 칸을 지금의 폴더 가져오기 화면(`FolderList`)으로 바꾼다. 읽은 결과를 다시 쓴다(새로 읽지 않는다).
- 가져온 뒤:
  - 1곳 이상이면 지금 문장(`resultMessage`)의 토스트에 단추 `보관함에서 보기`. 누르면 보관함(`/`)으로 가서 그 라벨로 거른다(검색어·지역·라벨 없음 필터는 비우고, F2의 방문 필터도 `전체`로 — 새로 넣은 곳은 안 가 본 곳이라 `가 본 곳`에서 보이지 않으므로. F2 설계서 §4.4와 같은 규칙). 지금 화면의 필터는 바로 바꾸지 않는다(라벨 관리에서 열었을 때 화면이 바뀌지 않게, §12 결정 10).
  - 0곳이면 토스트 `‘<폴더 이름>’ 폴더를 확인했어요`.
  - 추가 흐름을 닫는다.
- 고른 순간의 최신 보관함으로 다시 판단한다(§6.1). 미리보기의 표시는 화면에 보이는 보관함 기준의 안내다.

### 4.4 읽는 중·오류

`FolderPreview`의 읽는 중·오류 화면을 쓴다. 연결된 폴더일 때만 제목과 몇 문구가 다르다.

| 경우 | 제목 | 문구 | 단추 |
|---|---|---|---|
| 읽는 중 | `네이버 폴더 다시 가져오기` | `새로 저장한 곳을 찾는 중…` | `취소` |
| `NOT_FOUND` | 같음 | `폴더를 찾지 못했어요. 네이버 지도에서 폴더 공유를 껐거나 폴더를 지웠을 수 있어요` | `취소`, `연결 끊기` |
| `TOO_MANY_PLACES` | 같음 | `장소가 너무 많은 폴더예요(최대 1,000곳)`(지금 문구) | `취소` |
| `UPSTREAM_ERROR`·`TIMEOUT`·`OFFLINE` | 같음 | 지금 문구 | `취소`, `다시 시도` |
| 누른 순간 연결이 없어짐(다른 탭이 끊음·라벨을 지움) | — | 칸 안 알림 `폴더 연결이 바뀌었어요. 창을 닫고 다시 열어 주세요` | 단추는 그대로 다시 켠다 |

연결이 없는 폴더(첫 가져오기)의 문구는 지금 그대로다.

## 5. 데이터 (C5)

### 5.1 어디에 두나

보관함 문서(`tripmap:library:v2`, `schemaVersion` 2 그대로)에 **선택 컬렉션 `folders`** 를 더한다. 키는 공유 ID.

- 라벨 필드로 두지 않는 이유: 한 라벨에 폴더가 여럿일 수 있고, 라벨 스키마는 모든 곳(보관함·공유 내보내기 라벨 등)이 쓴다.
- 별도 저장 키로 두지 않는 이유: 가져오기와 연결 기록이 한 `LibraryStore.update` 안에서 함께 저장돼야 하고(한쪽만 남지 않게), F1 백업(C3: 보관함 문서 전체)에 저절로 들어간다.

### 5.2 형식

```ts
// src/schema/library.ts
export const NaverSid = Schema.String.check(Schema.isPattern(/^\d+$/, { message: 'sid는 숫자입니다' }));
export const ShareId = Schema.String.check(
  Schema.isPattern(/^[0-9a-zA-Z]+$/, { message: '공유 ID는 영문·숫자입니다' }),
);
export const FolderLinkSchema = Schema.Struct({
  shareId: ShareId,
  name: FieldSchema(Schema.String.check(Schema.isMaxLength(LIBRARY_LIMITS.folderNameChars))), // 100
  labelId: FieldSchema(LabelId),
  seenSids: FieldSchema(Schema.Array(NaverSid).check(Schema.isMaxLength(LIBRARY_LIMITS.folderSids))), // 1000
  checkedAt: IsoDateTime,
  createdAt: IsoDateTime,
  deletedAt: Schema.NullOr(IsoDateTime),
});

LibrarySchema = Struct({
  schemaVersion, places, labels, trips,
  folders: Schema.optionalKey(Schema.Record(Schema.String, FolderLinkSchema)),
})
```

- 공유 ID 패턴은 서버(`src/server/resolve.ts`의 `SHARE_ID`)와 같다. 서버가 받은 ID는 늘 통과한다.
- 문서 검사(지금 `.check` 필터에 더함): 키 = `shareId`(`키와 id가 다릅니다`), 살아 있는 연결의 라벨이 살아 있음(`없는 라벨입니다`).
- 바뀌는 값은 다른 필드처럼 `FieldSchema`(LWW)다. `checkedAt`은 바뀔 때마다 그 자체가 시각이라 묶지 않는다.
- `emptyLibrary()`는 그대로(`folders` 없음). 읽는 쪽은 `lib.folders ?? {}`로 본다.
- 크기: 연결 하나에 `sid` 1,000개면 약 13KB. 보관함 한도(`libraryChars` 4,000,000)에 비해 작다.

### 5.3 옛 버전과 롤백 (코드로 확인)

- 모든 옛 버전(`v0.1.0`~`v0.7.2`, effect 4.0.2)은 `LibraryStore`가 `safeParse(LibrarySchema, json)`으로 읽는다(`src/services/library-store.ts`의 `parseLibrary`, 태그마다 `git show <태그>:src/services/library-store.ts`로 확인). `safeParse`는 `onExcessProperty`를 넘기지 않으므로(`src/schema/parse.ts`) Effect 기본값 `"ignore"`가 쓰인다. `node_modules/effect/src/SchemaAST.ts`의 `ParseOptions` 설명: `"ignore"`(기본)는 모르는 키를 **떼어 낸다**. 구조체 파싱도 `onExcessProperty === "error"`일 때만 모르는 키를 오류로 본다.
- 그래서 옛 버전은 `folders`가 있는 문서를 **손상으로 보지 않고** 읽는다. 다만 그 버전에서 무엇이든 저장하면(`update`가 `JSON.stringify(parsed.data)`를 쓴다) `folders`가 **사라진다.** 장소·라벨·여행은 그대로다.
- 다시 `v0.10.0`으로 오면 연결만 없다. 같은 링크를 한 번 붙여 넣으면 다시 생긴다(§3.3).
- F1·F2가 더한 필드(C1, C3)도 같은 규칙이다. `v0.8.0`·`v0.9.x`는 `folders`를 모르므로 위와 같다.
- `docs/rollback.md` 표의 `v0.10.0` 줄 마지막 칸(F2 줄과 같은 꼴): `✅ 그대로 읽음. ⚠️ 옛 버전에서 저장하면 네이버 폴더 연결이 지워져, 돌아온 뒤 폴더 링크를 한 번 더 붙여 넣어야 다시 가져오기를 쓸 수 있음(장소·라벨은 그대로)`. 병합 뒤 별도 문서 PR(`docs: 롤백 표에 v0.10.0`)로 넣는다.
- 코드 되돌리기(PR 되돌림)도 같다: 스키마가 `folders`를 모르게 되어 다음 저장에서 지워진다. 손상 화면은 없다.
- 확인 시험: 옛 모양(`folders` 없는 구조체)으로 새 문서를 읽으면 통과하고 결과에 `folders`가 없다(§9).

## 6. 구조

### 6.1 도메인 (`src/domain/library/folder-links.ts`, 새 파일)

입력을 바꾸지 않는 순수 함수. `LibraryStore.update` 안에서 최신본에 적용한다.

```ts
export function folderLinks(lib: Library): Record<string, FolderLink>;          // lib.folders ?? {}
export function liveFolderLink(lib: Library, shareId: string): FolderLink | undefined; // 살아 있고 라벨도 살아 있는 연결
export function folderLinksOfLabel(lib: Library, labelId: string): FolderLink[];        // 폴더 이름순
export type FolderLinkInput = { shareId: string; folderName: string; labelId: string; seenSids: readonly string[] };
export function recordFolderLink(lib: Library, input: FolderLinkInput, ctx: OpCtx): Library;
export function unlinkFolder(lib: Library, shareId: string, ctx: OpCtx): Library;

export type FolderSyncPlan = {
  fresh: { item: FolderItem; mark: 'in-library' | 'deleted' | null }[];
  deleted: FolderItem[];
  unchanged: number;
  missing: { sid: string; placeId: string; name: string; address: string }[];
};
export function planFolderSync(lib: Library, link: FolderLink, items: readonly FolderItem[]): FolderSyncPlan;
export function syncFolder(
  lib: Library,
  input: { shareId: string; folderName: string; items: readonly FolderItem[]; pickedSids: readonly string[] },
```

- `syncFolder` = `importFolder(고른 항목, { labelId: 연결의 라벨 })` → `recordFolderLink(본 장소 = 폴더의 모든 sid)`. 장소를 넣는 규칙은 새로 만들지 않는다.
- `recordFolderLink`는 이름을 다듬어 100자로 자르고, `sid`는 중복·숫자 아닌 것을 빼고 1,000개까지만 남긴다(서버가 1,000곳 넘는 폴더를 이미 막는다).
- 라벨 연산(`src/domain/library/ops.ts`)의 `deleteLabel`·`mergeLabels`가 §3.4대로 연결을 고친다. `ops.ts`는 첫 화면 번들에 있으므로 `folder-links.ts`를 가져오지 않고 안에 작은 도우미를 둔다.

## 7. 오류 처리

- 조회 오류는 §4.4. 문구는 `PlaceLookupError.userMessage`를 쓰고, 연결된 폴더의 `NOT_FOUND`만 `FolderPreview`가 다른 문구를 고른다.
- `syncFolder`가 `NotFound`로 거절되면(누르는 사이 연결이 없어짐) 칸 안 알림(§4.4)을 보이고 미리보기·선택은 그대로 둔다. 저장소 오류(용량 등)는 지금처럼 앱 오류 보고자가 알린다.
- 칸이 닫힌 뒤 늦게 온 결과는 지금처럼 버리고, 저장이 끝났으면 토스트만 보인다(`aliveRef` 방식).
- 서버가 받은 폴더 이름이 100자를 넘어도 잘라 저장하므로 문서 검사에 걸리지 않는다. 공유 ID는 서버와 같은 패턴이라 걸리지 않는다.

## 8. 첫 로딩 예산

- 첫 화면 번들에 들어가는 것: 스키마(`FolderLinkSchema`, 몇백 바이트), `ops.ts`의 연결 도우미. 예산 `initialJsGzipMax` 327,680(지금 측정 297,769, 2026-10-14)에 견줘 무시할 크기.
- `FolderResync`는 이미 나뉜 `FolderPreview` 단위에, `folder-links.ts`는 `FolderPreview`·`LabelsPage` 단위에 들어간다. 새 `lazyChunk`도, `build:ci`의 `--require-lazy` 추가도 없다.

## 9. 시험

**단위**

- 스키마: `folders` 없는 문서·있는 문서 통과, 키≠`shareId` 거절, 살아 있는 연결의 라벨이 없거나 지워졌으면 거절(지운 연결은 통과), 이름 101자·`sid` 1,001개·숫자 아닌 `sid`·영숫자 아닌 공유 ID 거절. **옛 모양 구조체로 새 문서를 읽으면 통과하고 `folders`가 없다.**
- `folder-links`: 기록(새로·덮어쓰기·지운 연결 되살리기, 이름 자르기, `sid` 정리), 끊기, `planFolderSync` 네 분류(표 §3.2의 각 칸, 중복 `sid`), `syncFolder`(개수, 본 장소·확인한 시각 갱신, 고르지 않은 새 곳도 본 장소에, 지운 곳 되살리기, 연결 없음·라벨 지워짐 → `NotFound`, 결과가 `LibrarySchema` 통과).
- 라벨 연산: 지우면 연결도 지워짐, 합치면 연결이 옮겨 감.
- 서버: `/api/naver-folder`가 `fresh=1`이면 캐시를 보지 않고 같은 키에 저장(지금의 `장소·폴더는 fresh=1을 몰라` 시험은 장소만 남긴다). `lookupFolder(…, { fresh: true })`의 주소.
- 화면: 첫 가져오기가 연결을 남김, 연결된 링크 → 다시 가져오기 화면(여행 대상이 있으면 아님), 기본 체크·표시 글자·빈 상태·`확인했어요`, 두 번 눌러도 한 번, `폴더 전체 보기`, `NOT_FOUND` → `연결 끊기`, 라벨 고치기 구역·접근 이름·포커스(칸 안으로, 닫으면 라벨 줄로), 라벨 줄 글자, 지우기 확인 문구.

**E2E** (`tests/e2e/folder-resync.spec.ts`, 세 프로젝트): 폴더를 링크로 가져오고(녹화 응답 3곳) → 응답을 4곳으로 바꾸고 → `/labels` → 라벨 → `새로 저장한 곳 가져오기` → `새로 저장한 곳 1 · 그대로 3 · 폴더에서 빠진 곳 0` → `1곳 가져오기` → 토스트 `1곳을 새로 넣었어요` → `보관함에서 보기` → 4곳. 다시 가져오기 요청에 `fresh=1`. 데스크톱 한 개를 `@smoke`로.

## 11. 묶음 사이 약속

- **C3 (F1 백업)**: 보관함 문서 전체를 담으므로 `folders`도 들어간다. F1에 바라는 것: 복원이 문서를 **갈아 끼우는** 방식이면 할 일이 없다. **합치는** 복원을 넣는다면 `folders`는 공유 ID로 맞추고 필드마다 LWW(`pickField`), `checkedAt`은 늦은 쪽으로 합쳐 주기를 바란다. `v0.10.0` 백업을 `v0.8.0`·`v0.9.x`에서 복원하면 `folders`는 빠진다(§5.3).
- **C1 (F2)**: 상관없다. 다시 가져오기는 기존 장소의 `visitedOn`·`review`를 건드리지 않는다(`mergeInto`가 라벨·메모·`saved`만 고친다).
- **C4 (F7)**: 공유 형식에 폴더 연결을 넣지 않는다.
- **C2·C6**: 상관없다.

## 12. 결정이 필요한 것

각 항목은 추천안으로 설계했다. 바꾸면 해당 절과 계획을 고친다.

1. **폴더 기록 위치 (C5)** — 선택지: (가) 보관함 문서의 선택 컬렉션 `folders` / (나) 라벨에 선택 필드 / (다) 별도 저장 키 `tripmap:folders:v1`. **추천 (가)**. 이유: 가져오기와 한 번에 저장되고, F1 백업에 저절로 들어가며, 한 라벨에 폴더 여럿을 둘 수 있다. (다)는 옛 버전이 건드리지 않아 롤백에 강하지만 백업·원자성을 따로 챙겨야 한다.
2. **"새로 저장한 곳" 판단** — (가) 지난번에 본 `sid` 목록 / (나) 네이버 `creationTime` > 지난 확인 시각 / (다) 보관함에 없는 곳 전부. **추천 (가)**. 이유: 네이버 시각 규칙(폴더 옮기기 등)을 확인하지 못했고, (다)는 보관함에서 지운 곳을 매번 다시 내민다.
3. **폴더에서 빠진 곳** — (가) 알리기만 / (나) `이 라벨 떼기` 선택을 준다 / (다) 장소를 지운다. **추천 (가)**. 이유: 내 정리본을 덮지 않는다는 원칙. (나)는 다음 묶음에서 더하기 쉽다.
4. **보관함에서 지운 곳** — (가) 따로 묶어 체크 없이 보이기 / (나) 숨기기 / (다) 새 곳처럼 체크해 되살리기. **추천 (가)**. 이유: 기본은 사용자의 삭제를 지키고, 실수로 지운 것은 한 번에 되살릴 수 있다.
5. **진입점** — (가) 라벨 고치기 대화상자 + 같은 링크 붙여 넣기 / (나) 보관함 라벨 칩의 메뉴 / (다) 설정의 `네이버 폴더` 목록. **추천 (가)**. 이유: 칩은 지금 누르면 거르는 토글이라 메뉴를 얹기 어렵고, 연결은 라벨에 붙는다. (다)는 결정 7과 함께 생각할 만하다.
6. **연결된 링크를 다시 붙여 넣으면** — (가) 다시 가져오기 화면, `폴더 전체 보기`로 전환 / (나) 늘 지금 화면. **추천 (가)**. 이유: 사용자가 링크로 다시 가져오는 습관을 그대로 쓸 수 있다.
7. **여러 폴더 한 번에** — (가) 이번엔 안 함 / (나) 라벨 관리 위에 `네이버 폴더 모두 확인`(폴더마다 새 곳 수를 보이고 하나씩 연다) / (다) 한 화면에서 모두 가져오기. **추천 (가)**. 이유: 폴더마다 라벨·선택이 달라 한 화면이 복잡해지고, 서버 요청이 폴더 수만큼 몰린다. 써 본 뒤 (나)를 다음 묶음으로.
8. **고르지 않은 새 곳** — (가) 본 것으로 기억(다음엔 `그대로`) / (나) 다음에도 새 곳으로 다시 보이기. **추천 (가)**. 이유: 매번 같은 곳을 다시 묻지 않는다. 필요하면 `폴더 전체 보기`.
9. **다시 가져오기의 캐시** — (가) 연결된 폴더만 `fresh=1` / (나) 폴더 조회는 늘 `fresh=1` / (다) 캐시 시간을 줄이기. **추천 (가)**. 이유: 방금 저장한 곳이 보여야 하는 건 다시 가져오기뿐이다.
10. **가져온 뒤 필터** — (가) 바꾸지 않고 토스트 `보관함에서 보기` / (나) 지금 가져오기처럼 바로 그 라벨로 거름. **추천 (가)**. 이유: 라벨 관리에서 열었을 때 보던 화면이 그대로 남는다.
11. **라벨을 지우거나 합칠 때** — (가) 지우면 연결도 끊고 합치면 옮김 / (나) 연결은 남기고 다시 가져올 때 라벨을 새로 고르게. **추천 (가)**. 이유: 불변식이 단순하고(살아 있는 연결 → 살아 있는 라벨), 다시 가져오기 화면에 라벨 고르기가 필요 없다.
