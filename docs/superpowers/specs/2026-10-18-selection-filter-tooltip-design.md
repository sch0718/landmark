- 작성일: 2026-10-18
- 상태: 설계 (리뷰 대기)
- 태그: `v0.14.2`
- 관련 문서: `2026-10-08-place-library-design.md`(§4.1 셸, §4.2 목록, §4.5 지도), `2026-10-16-nearby-design.md`(근처 모드 맞추기), `2026-10-14-design-qa-design.md`(접근성 기준). 충돌하면 이 문서가 우선한다.
- 짝 묶음: A2(휴대폰 아래 시트·라벨 고르기 창, 별도 세션). A1은 휴대폰(compact) 상세 구조와 상세의 라벨 칸을 바꾸지 않는다.

## 1. 목적

사용자 데이터(장소 3,202곳·라벨 53개)로 쓰면서 나온 불편 넷을 휴리스틱 원칙에 맞춰 고친다.

| # | 불편 | 원칙 |
|---|---|---|
| 1 | 장소를 고르면 풀 방법이 없다(넓은 화면엔 닫기도 없음). 중간 화면 X는 지도에서 들어와도 목록(`/`)으로 간다. | 3. 사용자 제어와 자유 |
| 2 | 라벨로 거르면 지도가 결과가 아니라 열어 둔 장소로 확대된다(인제 `고향집`을 연 채 `서울 카페&베이커리`로 거르면 인제로 감). | 1. 시스템 상태 보이기 |
| 3 | 잘린 이름의 전체를 볼 방법이 없다. 라벨 53개 중 41개가 같은 머리말로 시작해 잘리면 구분이 안 된다. | 6. 기억보다 알아보기 |
| 4 | `라벨 관리`가 칩 53개 가로 스크롤 줄 맨 끝에 숨어 편집 기능이 없는 줄 알았다. | 6·10. 알아보기·도움말 |

## 2. 성공 기준

1. 넓은·중간 화면에서 장소를 연 뒤 **고른 마커 다시 누르기 / 지도 빈 곳 누르기 / Esc / 상세의 X** 중 어느 것으로도 선택이 풀린다.
2. 선택을 풀면 주소는 연 곳(`/` 또는 `/map`)으로 돌아가고, 목록 칸은 열기 전 스크롤 위치(벤토·타일 보기면 라벨 블록이 보이던 자리)로 돌아간다.
3. 장소를 연 채 라벨·지역·검색·방문·미분류·모두 포함을 바꾸면 지도는 **결과 전체**에 맞는다. 열린 장소가 결과에 없으면 선택이 풀리고, 있으면 선택(마커 강조·상세)은 그대로다.
4. 근처 모드의 반경 맞추기는 지금처럼 동작한다.
5. 아래 §5.3 목록의 잘리는 곳에서 **실제로 잘렸을 때만** 마우스 오버·키보드 포커스로 전체 이름 툴팁이 뜬다. 잘리지 않았으면 뜨지 않는다.
6. `라벨 관리`는 칩 줄 맨 앞에 있어 스크롤하지 않아도 보인다.
7. 저장 형식(`tripmap:library:v2` schemaVersion 2, `tripmap:prefs`)은 그대로다. `yarn build:ci` 통과, 첫 로딩 예산(`initialJsGzipMax` 327,680) 안.

## 3. 선택 해제 (원칙 3)

### 3.1 닫기 함수 하나

지금 `AppShell.closeDetail`이 하는 일을 공유 훅 `useCloseDetail()`로 옮기고, 셸의 X·지도·Esc가 모두 이것을 부른다.

- **연 곳 기억**: 지금 compact 전용인 `origin`(`'list' | 'map'`, 장소가 열리지 않은 보관함 경로를 볼 때 갱신)을 모든 폭에서 쓰도록 jotai atom으로 옮긴다(셸이 쓰고 지도·훅이 읽는다).
- **넓은·중간**: `origin`이 지도면 `/map`, 목록이면 `/`로 간다(지금처럼 기록을 쌓는다. 뒤로가기로 방금 장소를 다시 열 수 있다).
- **좁은(compact)**: 지금 동작 그대로(앱 안에서 연 기록이 있으면 `navigate(-1)`, 없으면 `origin` 경로로 교체). A2가 시트를 바꿔도 이 함수는 그대로 쓴다.

### 3.2 해제 수단

| 수단 | 동작 | 폭 |
|---|---|---|
| 고른 마커 다시 누르기 | 열린 장소의 마커를 누르면 닫는다(지금은 같은 주소로 다시 navigate만 함). | 지도가 보이는 모든 폭 |
| 지도 빈 곳 누르기 | 마커·클러스터·지도 위 단추가 아닌 곳을 누르면 닫는다. 끌기(패닝)·핀치는 누르기가 아니다. | 지도가 보이는 모든 폭 |
| Esc | 장소가 열려 있으면 닫는다. 아래 예외는 무시. | 모든 폭 |
| X 단추 | 넓은 화면 상세 칸(`column`)에도 장소가 열렸을 때 `닫기` X를 둔다(안내만 보일 때는 없음). 중간 화면 X는 §3.1대로 연 곳으로. | 넓은·중간 |

- **지도 빈 곳**: 지도 어댑터에 `onMapClick(cb)`를 더한다. 네이버는 지도 `click` 이벤트(끌기와 구분해 주는 SDK 이벤트), 가짜 어댑터는 캔버스 바탕 클릭. 마커 DOM 클릭이 지도 클릭으로 함께 오지 않는지 실제 네이버 지도에서 확인하고, 오면 마커 쪽에서 막는다.
- **핀 모드·추가 흐름 중**에는 마커 다시 누르기·빈 곳 누르기로 닫지 않는다(핀 모드는 지금도 마커 클릭을 무시, 빈 곳 누르기는 조준점 조작과 겹친다).
- **Esc 예외**(그쪽 몫): 입력칸·`contenteditable`에 포커스가 있을 때, 한글 조합 중, 이미 다른 처리기가 `preventDefault`/전파 중단한 Esc(MUI 대화상자·메뉴, 추가 칸, 핀 모드), 대화상자가 열려 있을 때.
- **닫은 뒤 포커스**: 닫는 단추·상세 안에 포커스가 있었으면 사라지므로, 열었던 목록 행이 화면에 있으면 그 행, 없으면 `#main`으로 옮긴다(`preventScroll`).

### 3.3 목록 칸 되돌리기

- 장소가 **열리지 않은 상태에서 열릴 때**(첫 선택) 목록 스크롤 칸의 `scrollTop`을 기억한다. 열린 채 다른 장소로 바꿀 때는 덮어쓰지 않는다.
- 닫히면(어느 수단이든, 브라우저 뒤로가기 포함) 기억한 `scrollTop`으로 돌린다. 그사이 필터가 바뀌었으면 돌리지 않는다(위치가 의미 없음).
- 다시 고를 때 목록이 그 행으로 스크롤하는 기존 동작(`focusPlaceAtom`)은 그대로다.

### 3.4 지도 카메라

닫을 때 카메라는 움직이지 않는다(사용자가 보던 곳 유지). 중간 화면 오버레이가 사라질 때 지금처럼 그대로 둔다.

## 4. 거를 때 지도 (원칙 1)

`LibraryMap.tsx`의 "필터가 바뀌면 열린 장소로 다시 모으기"(`seenQueryKey` 블록)를 없애고 다음으로 바꾼다.

1. `query`가 바뀌면 지도는 `fitKey`로 결과 전체에 맞춘다(지금 `MapView` 동작).
2. 열린 장소가 **새 결과에 없으면 선택을 푼다**(§3.1 닫기 함수, 주소 교체로 — 거르기 한 번에 기록 두 개가 쌓이지 않게). 이때 `toMarkers`가 결과 밖 열린 장소를 강제로 넣는 규칙도 맞추기 대상에서 빠지므로 카메라가 그 장소로 끌려가지 않는다.
3. 열린 장소가 **결과 안에 있으면** 선택·강조는 유지하고 카메라는 결과 전체 그대로(그 장소로 확대하지 않는다).
4. **근처 모드**: 기존 규칙을 그대로 지킨다. 반경 상자 맞추기(`extraFitPoints`, `fitMarkers={false}`)는 그대로이고, 근처 쪽 변화(켜기·반경·새 위치·`내 위치 보기`)는 선택을 풀지 않는다(열린 장소는 반경 밖이어도 마커를 보인다). 근처 모드에서 `query`를 바꿀 때 "결과"는 반경 안 장소(`nearby.places`)다.
5. 직접 주소로 들어오거나(`/place/:id`) 거르기 없이 장소를 고를 때는 지금처럼 그 장소로 옮긴다. 결과 밖 장소를 주소로 연 경우 마커를 강제로 보이는 기존 규칙도 유지한다(풀기는 **거르기가 바뀐 순간**에만).

같은 필터의 옛 카메라 되살리기(`MapView`의 `cameras` 캐시)는 그대로 둔다.

## 5. 긴 이름 툴팁 (원칙 6)

### 5.1 공통 컴포넌트 `TruncatedText`

`src/components/TruncatedText.tsx`.

- 글자를 말줄임 스타일(한 줄 `nowrap` 또는 `lines={n}` 줄 제한)로 그린다. 기존 각 곳의 `sx`를 이것으로 바꾼다.
- 열 때마다 잰다: 한 줄은 `scrollWidth > clientWidth`, 여러 줄은 `scrollHeight > clientHeight`. **잘렸을 때만** MUI `Tooltip`을 연다(잘리지 않았으면 아무것도 안 뜸).
- 여는 계기: 글자(또는 그것을 감싼 조작 요소) 위 마우스 오버, 감싼 조작 요소(행·칩·단추)가 **키보드 포커스(`:focus-visible`)** 를 받을 때, 터치 길게 누르기(§5.2).
- 툴팁 내용은 같은 문자열을 React 텍스트로 넣는다. DOM에 이미 전체 글자가 있으므로 접근 이름은 바뀌지 않는다(행·칩 단추의 이름 그대로).
- 툴팁은 MUI가 이미 번들에 있으므로 첫 로딩 예산 영향은 작다. 예산은 `yarn build:ci`로 확인한다.

### 5.2 터치

- 기본: 길게 누르기(MUI `enterTouchDelay`, 약 500ms)로 열고 손을 떼고 잠시 뒤 닫는다.
- **예외 — 길게 누르기가 이미 다른 뜻인 곳**: 보관함 행·카드(`PlaceRow`/`PlaceCard`와 그 안의 라벨 칩, 길게 누르기 = 선택 모드)에서는 터치 툴팁을 켜지 않는다. 그 장소의 전체 이름은 열면 상세 제목에서 줄바꿈으로 다 보인다. 마우스·키보드 툴팁은 켠다. 계획 화면 후보는 끌기 손잡이가 따로 있어 이름 단추의 길게 누르기와 겹치지 않는다.

## 6. `라벨 관리` 위치 (원칙 6·10)

`LabelChips.tsx`의 `라벨 관리` 링크를 칩 줄 **맨 앞**(방문·근처 칩 `leading`보다도 앞)에 고정한다.

- 가로 스크롤해도 보이도록 왼쪽에 붙인다(`position: sticky; left: 0`, 줄 바탕색 + 오른쪽 구분선). 접근성 순서도 맨 앞.
- 모양은 지금 그대로(태그 아이콘 + `라벨 관리`, 44px 높이).
- `manageLink={false}`(보관함 고르기 창)는 그대로 없음.

## 7. 범위 밖

- 휴대폰 상세를 지도 위 아래쪽 시트로, 상세 라벨 칸을 붙은 라벨만 + 고르기 창으로(A2).
- 라벨 이모지·자동 아이콘(B), 앱 아이콘(C), 라벨 검색·지역 2단계·성능(D), 링크 공유(E).
- 저장 형식·선호 키 변경.

## 8. 시험

- 단위(Vitest): `TruncatedText`(잘림 여부에 따라 툴팁 열림/안 열림, 포커스로 열림), `useCloseDetail`(폭·연 곳별 이동), `LabelChips`(`라벨 관리`가 첫 조작 요소), 지도 거르기 규칙(결과 밖이면 닫힘·안이면 유지, 근처 모드), 마커 다시 누르기·빈 곳 누르기(가짜 어댑터), Esc 예외.
- E2E(Playwright, 가짜 지도): 넓은·중간 폭에서 마커로 열고 다시 눌러 닫기, 빈 곳·Esc·X로 닫기와 주소, 목록 스크롤 복원, 라벨로 걸러 결과 밖 장소가 닫히는 흐름, 휴대폰 폭 칩 줄 첫 요소.
- 브라우저 확인: 사용자 백업 데이터로 넓은(1440)·중간(1024)·휴대폰(375)에서 §1의 재현을 고친 뒤 다시 확인(실제 네이버 지도, 포트 8788).
