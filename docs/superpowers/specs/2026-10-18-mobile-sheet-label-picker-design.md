## 1. 목적과 성공 기준

### 1.1 목적

사용자 데이터(장소 3,202곳·라벨 53개, 네이버 폴더 53개에서 가져옴)로 쓰면서 나온 두 불편을 고친다. 휴리스틱 10원칙에 맞춘 설계를 사용자가 승인했다.

1. **휴대폰에서 지도 맥락이 사라진다(원칙 3 통제, 원칙 6 기억보다 인식).** 지도에서 마커를 누르면 상세가 화면 전체를 덮어 지도가 안 보인다. 다른 장소를 보려면 뒤로 갔다가 다시 눌러야 한다.
2. **상세의 라벨 칸이 너무 길다(원칙 8 미적·최소 디자인, 원칙 7 효율).** 라벨 53개를 모두 칩으로 펼쳐, 휴대폰에서는 몇 화면을 내려야 메모가 나온다. 넓은 화면 오른쪽 칸도 길다.

### 1.2 재현 (2026-10-18, 사용자 백업, 375×812)

- `/map`에서 장소를 고르면 `/place/:id`로 가고 `DetailPane mode="sheet"`(`position: fixed`, 화면 전체)가 지도를 덮는다. 위에는 `‹`(`목록으로`) 하나뿐이다.
- 라벨 칸(`LabelPicker`)에 칩 53개(+ `새 라벨 이름` 입력란)가 줄줄이 보인다. 상세 화면 대부분이 라벨이다.

### 1.3 성공 기준

1. 휴대폰 지도 화면에서 마커를 누르면 지도 위 아래쪽에 시트가 **반쯤** 열린다. 이름·주소·분류·`네이버 지도에서 열기`·`다녀옴`이 보이고, 지도와 위쪽 필터 칩은 그대로 보이고 눌린다.
2. 반쯤 열린 채로 다른 마커를 누르면 시트 내용만 그 장소로 바뀐다. 뒤로 가기 한 번이면 시트가 닫히고 지도로 돌아간다.
3. 시트를 끌어 올리거나 `펼치기` 버튼을 누르면 전체 상세가 된다. 끌어 내리거나 `닫기` 버튼·Esc를 누르면 닫히고 선택이 풀린다(`/map`).
4. 휴대폰 목록 화면에서 장소를 고르면 **같은 시트가 다 펼친 채로** 열린다(지금과 보이는 양이 같다).
5. 주소(`/place/:id`)를 새로고침하거나 링크로 바로 들어와도 같은 장소가 시트로 열린다.
6. 키보드·스크린리더만으로 시트를 열고, 펼치고, 접고, 닫을 수 있다(끌기 없이).
7. 모든 화면 크기에서 상세의 라벨 칸은 **붙은 라벨만** 보이고, `라벨 바꾸기`로 검색 칸이 있는 고르기 창을 연다. 창에서는 많이 쓴 순으로 체크 목록이 보이고, 이름으로 거르고, 새 라벨을 만들어 붙일 수 있다.
8. 장소 추가 확인 카드(링크·핀)의 라벨 칸도 같은 모양이다.
9. 저장 형식(`tripmap:library:v2` schemaVersion 2, `tripmap:prefs`)은 바뀌지 않는다.
10. 첫 로딩 JS(gzip)가 예산 327,680 안이다. 라벨 고르기 창은 첫 로딩에 들어가지 않는다(`--require-lazy LabelPickerDialog`).

## 2. 범위

### 2.1 하는 것

- 휴대폰(compact, <768) 상세를 지도·목록 위 아래쪽 시트(`PlaceSheet`)로 바꾼다. 반쯤/다 펼침 두 단계, 끌기와 버튼.
- 휴대폰에서 장소를 여는 기록 규칙(누를 때마다 쌓지 않고 바꿔치기), 새로고침·바로 들어오기 처리.
- 휴대폰 지도가 시트에 가려지지 않도록 지도 여백을 맞춘다.
- 라벨 칸(`LabelPicker`)을 붙은 라벨 + `라벨 바꾸기` 버튼으로 바꾸고, 라벨 고르기 창(`LabelPickerDialog`, lazy)을 새로 만든다. 상세·여행 계획 안 상세·추가 확인 카드(`CandidateCard`·`PinCard`) 모두 같은 컴포넌트를 쓴다.

### 2.2 안 하는 것

- 선택 해제 방법(마커 다시 누르기·지도 빈 곳·Esc 전역 처리·넓은 화면 X), 거를 때 지도 맞춤, 긴 이름 툴팁, `라벨 관리` 링크 위치 → A1.
- 중간·넓은 화면의 상세 배치(오른쪽 칸·오버레이)는 그대로 둔다. 라벨 칸만 바뀐다.
- 라벨 이모지(B), 앱 아이콘(C), 라벨 필터 검색·지역 2단계·성능(D), 링크 공유(E).
- 일괄 선택의 `라벨 붙이기`·`라벨 떼기` 메뉴(`BulkBar`)는 그대로 둔다.
- 시트의 펼침 단계를 저장하지 않는다(§4.4).

## 3. 지금 있는 것 (코드에서 확인, 2026-10-18 `fc7c062`)

- `AppShell`(`src/sections/shell/AppShell.tsx`): compact면 본문에 지도 또는 목록 한 칸을 두고, `placeId`가 있으면 `DetailPane mode="sheet"`(fixed, `inset: 0`, zIndex 1100)를 덮는다. 뒤에 깔 화면은 `origin` 상태(`'list' | 'map'`, 마지막으로 본 쪽, 새로고침하면 `'list'`)로 정한다. 닫기는 앱 안에서 연 기록이 있으면 `navigate(-1)`, 없으면 `origin` 경로로 `replace`.
- 장소를 여는 곳: 목록 `LibraryPage`의 `onOpen` → `navigate(paths.place(id))`, 지도 `LibraryMap`의 `onMarkerClick` → `navigate(paths.place(id))`(늘 push). 추가 카드는 저장 뒤 `navigate(paths.place(createdId))`.
- `LibraryMap`: 중간 폭에서 상세가 지도를 덮으면 오른쪽 여백(`OVERLAID_PADDING`)을 두고, 덮개가 새로 생길 때 열어 둔 장소로 다시 모은다. 마커로 연 장소는 카메라를 옮기지 않는다(`fromMarker`). `MapView`의 `focus`는 여백을 뺀 영역 가운데로 옮긴다(줌 16).
- 상세(`PlaceDetail`) 순서: 이름(h1)·주소·분류·`네이버 지도에서 열기`·다녀옴·한 줄 평·라벨·메모·삭제. 여행 계획 화면(`TripPlannerPage`)도 같은 상세를 `headingLevel={2}`로 쓴다.
- `LabelPicker`: 살아 있는 라벨 전부를 `ChipButton`(aria-pressed)으로, 아래에 `새 라벨 이름` 입력란(Enter로 만들어 붙임, 거절 이유는 입력란 아래 `role="alert"`). 상세 외에 `CandidateCard`·`PinCard`도 같은 컴포넌트를 쓴다.
- 라벨 이름 비교는 `normalizeLabelName`(같은 이름이면 `createAndAttachLabel`이 새로 만들지 않고 그 라벨을 붙인다).
- 아래쪽 시트 선례: `AddSheet`(MUI `Drawer anchor="bottom"`, 모달). 상세 시트는 지도를 계속 눌러야 하므로 모달이 아니어야 한다.

## 4. 휴대폰 상세 시트

### 4.1 모양

```
 반쯤 (지도에서 고름)              다 펼침 (목록에서 고름 / 끌어 올림)
┌───────────────────────┐        ┌───────────────────────┐
│ [모두 포함][미분류]…   │ 필터칩  │ ▔▔▔▔  (손잡이)  [⌃][✕] │
│                       │        │ 멸치국수            ✎ │
│     ● 마커들 (지도)    │        │ 서울 은평구 …          │
│                       │        │ 분류 추가           ✎ │
├───────────────────────┤        │ [네이버 지도에서 열기] │
│ ▔▔▔▔ (손잡이)  [⌃][✕] │        │ 다녀옴 [다녀왔어요]    │
│ 멸치국수            ✎ │        │ 한 줄 평 …             │
│ 서울 은평구 …          │        │ 라벨 ◉서울 맛집 [라벨 바꾸기]│
│ 분류 추가           ✎ │        │ 메모 …                 │
│ [네이버 지도에서 열기] │        │ (스크롤)               │
│ 다녀옴 [다녀왔어요]    │        │                       │
├───────────────────────┤        ├───────────────────────┤
│ 보관함 지도 ＋ 여행 설정│ 하단 탭 │ 보관함 지도 ＋ 여행 설정│
└───────────────────────┘        └───────────────────────┘
```

- 시트는 본문(`main`) 안, 하단 탭 **위**에 붙는다. 하단 탭은 시트가 열려 있어도 늘 보이고 눌린다(지금은 전체 화면 시트가 탭까지 덮는다). 시트 뒤가 지도면 하단 탭의 `지도`가, 목록이면 `보관함`이 켜져 있다(`aria-current`). 넓은·중간 화면의 레일은 지금처럼 `보관함`.
- **반쯤**: 높이 `min(320px, 창 높이의 45%)`(`sheetHalfPx`, 지도 여백과 같은 값). 위 모서리 둥글게(`--tm-radius-xl`), 그림자 `--tm-shadow-2`. 안쪽은 스크롤하지 않고 잘린다. 320px이면 이름·주소·분류·`네이버 지도에서 열기`·다녀옴까지 보인다(따로 요약 화면을 만들지 않고 같은 `PlaceDetail`의 윗부분이 보이는 것이다).
- **다 펼침**: 본문 높이 전체(위쪽 안전 영역 `env(safe-area-inset-top)` 아래부터). 안쪽이 스크롤된다.
- 머리 줄(높이 44px): 가운데 손잡이 막대(36×4px, 장식), 오른쪽에 버튼 둘.
  - `펼치기`/`접기` 버튼(`aria-expanded`, 아이콘 ⌃/⌄). 반쯤 ↔ 다 펼침.
  - `닫기` 버튼(✕). 지금의 `목록으로`(‹)를 대신한다.
- 랜드마크는 지금처럼 `section aria-label="장소 상세"`. 모달이 아니다(`role="dialog"` 아님, 뒤 화면을 `inert`로 막지 않는다).
- 움직임: `transform: translateY` 200ms. `prefers-reduced-motion: reduce`면 바로 바뀐다.

### 4.2 끌기

- **반쯤일 때**: 시트 어디를 잡아도 끌린다(안쪽이 스크롤되지 않으므로 겹칠 동작이 없다). 손가락이 8px 넘게 움직여야 끌기로 보고, 끌기로 끝난 손짓은 그 뒤의 클릭을 삼켜 버튼이 눌리지 않게 한다.
- **다 펼침일 때**: 머리 줄(손잡이 줄)만 끌린다. 안쪽은 스크롤한다.
- 손을 떼면 놓인 위치와 빠르기로 단계를 정한다(순수 함수 `resolveSnap`, 단위 시험):
  - 빠르게 튕기면(0.5px/ms 넘게) 그 방향의 다음 단계로: 위 → 다 펼침, 아래 → (다 펼침이면) 반쯤, (반쯤이면) 닫힘.
  - 아니면 가장 가까운 단계(닫힘 = 높이 0, 반쯤, 다 펼침)로. 단, 다 펼침에서 한 번 끌어 바로 닫힘까지 가지는 않는다(반쯤에서 멈춘다) — 실수로 닫는 일을 줄인다.
- 끄는 동안 시트는 손가락을 따라가고(반쯤 높이 아래로도 내려간다), 지도 여백은 바꾸지 않는다.
- 끌기 영역은 `touch-action: none`, 다 펼침의 안쪽은 `overscroll-behavior: contain`.

### 4.3 여는 곳과 처음 단계

| 어디서 | 처음 단계 | 시트 뒤 화면 |
|---|---|---|
| 지도 화면(`/map`)의 마커 | 반쯤 | 지도 |
| 목록 화면(`/`)의 행·카드 | 다 펼침 | 목록 |
| 추가 카드에서 저장 뒤 이동 | 반쯤 | 지도 (compact 추가 흐름은 지도 화면에서만 열린다) |
| 새로고침 | 기록에 남은 단계·뒤 화면(§4.4) | 〃 |
| 링크로 바로 들어옴(기록에 상태 없음) | 반쯤 | 지도 (장소가 보이도록) |

- 반쯤으로 목록 위에 열린 시트(목록에서 연 뒤 끌어 내림)도 뒤의 목록은 눌린다. 다른 행을 누르면 시트 단계는 그대로 두고 장소만 바뀐다.
- 시트가 열린 채 다른 장소를 열면 단계를 유지한다(지도에서 누르면 늘 반쯤 상태다 — 다 펼침은 지도를 덮으므로).

### 4.4 주소와 기록

- 장소를 열 때 기록 상태(`location.state`)에 `{ sheet: { from: 'map' | 'list', snap: 'half' | 'full', inApp: boolean } }`를 넣는다. `inApp`은 앱 안에서 연 기록인가다(링크로 바로 들어오면 상태가 없어 `false`). 브라우저가 기록 상태를 새로고침에도 지키므로 뒤 화면과 처음 단계가 그대로 돌아온다. `tripmap:prefs`·localStorage에는 넣지 않는다.
- 펼치기·접기는 **지금 기록 항목의 상태만** 바꾼다(`replace`, 새 항목 없음 — 뒤로 가기 횟수는 그대로). 새로고침해도 그 단계 그대로다. 상태가 시트 단계의 유일한 출처라 따로 React 상태를 두지 않는다.
- **바꿔치기**(사용자 결정): compact에서 **이미 `/place/:id`에 있을 때** 다른 장소를 열면 `replace`한다. 처음 열 때만 `push`한다. 그래서 마커를 몇 번 눌러도 뒤로 가기 한 번이면 시트가 닫히고 지도(또는 목록)로 간다.
  - 중간·넓은 화면은 지금처럼 `push`한다(A1이 정하는 해제 동작과 겹치지 않도록 손대지 않는다).
  - 이 규칙은 `useOpenPlace()` 훅 한 곳에 두고 목록·지도·추가 카드가 함께 쓴다.
- **닫기**(버튼·끌어 내리기·Esc·뒤로 가기): 지금 `closeDetail`과 같다. 기록 상태의 `inApp`이 참이면 `navigate(-1)`, 아니면(링크로 바로 들어옴 — `replace`로 바뀐 항목은 `location.key`가 `default`가 아니므로 키 대신 이 값으로 판단한다) 뒤 화면 경로(`/map` 또는 `/`)로 `replace`. 바꿔치기 덕분에 `-1`은 늘 시트를 열기 전 화면이다.
- 다 펼침에서 뒤로 가기도 한 번에 닫는다(반쯤으로 접히지 않는다). 휴대폰 뒤로 가기가 늘 "화면을 떠난다"로 같게 동작하게 한다.
- 장소가 없거나 지워졌으면 지금처럼 시트 안에 `장소를 찾을 수 없어요`와 `보관함으로 돌아가기`를 보인다.
- 시트 안 `삭제`는 지금처럼 `/`로 `replace`하고 되돌리기 토스트를 띄운다.

### 4.5 지도

- compact에서 지도 위에 시트가 반쯤 열려 있으면(`placeId !== null` 그리고 뒤 화면이 지도) 지도 여백 아래쪽을 `sheetHalfPx + 40`으로 둔다. 필터 맞춤·장소 모으기가 시트에 가려지지 않는 영역을 쓴다.
- 시트가 **새로 생길 때**(닫혀 있다가 열림, 링크로 바로 들어옴) 열어 둔 장소를 가려지지 않는 영역 가운데로 모은다(중간 폭 오버레이가 새로 생길 때와 같은 규칙). 시트가 열린 채 마커를 눌러 장소만 바뀔 때는 카메라를 옮기지 않는다(지금의 `fromMarker` 규칙 — 누른 마커는 이미 보이는 자리다).
- 지도 오른쪽 위 단추(확대·축소·내 위치)는 위쪽이라 시트와 겹치지 않는다. 네이버 로고·축척은 시트 아래로 가려질 수 있다(중간 폭 오버레이와 같은 처리).

### 4.6 키보드·스크린리더

- 시트가 **닫혀 있다가 열리면** 포커스를 시트(`section`, `tabIndex={-1}`)로 옮긴다. 스크린리더는 `장소 상세` 영역과 장소 이름(h1)을 읽는다. 시트가 열린 채 장소만 바뀌면 포커스를 옮기지 않는다(지도·목록에서 계속 고를 수 있게).
- `펼치기`/`접기`·`닫기`는 보통 버튼이라 Tab으로 가고 Enter·Space로 누른다. 끌기 없이 모든 단계에 갈 수 있다.
- 반쯤일 때 잘려 안 보이는 부분(한 줄 평·라벨·메모·삭제)은 `inert`로 두지 **않는다**. 대신 Tab으로 시트 안의 가려진 요소에 포커스가 가면 시트를 다 펼친다(`focusin`에서 요소가 보이는 영역 밖이면 펼침). 키보드 사용자가 안 보이는 곳을 누르는 일이 없다.
- Esc: 포커스가 시트 안에 있으면 닫기와 같다. 입력 중(이름·분류·한 줄 평·메모 편집, 라벨 고르기 창)에는 그 편집기·창이 Esc를 먼저 쓴다(지금처럼 편집 취소·창 닫기). 시트는 이미 처리된 Esc(`defaultPrevented`)를 무시한다 — React 포털 이벤트는 React 트리를 따라 올라오므로 시트 안에서 연 라벨 고르기 창의 Esc가 시트까지 닫지 않게 한다. A1이 화면 전체 Esc(선택 해제)를 넣으면 병합 때 한 곳으로 합친다(§7).
- 포커스가 시트 안에 있던 채 시트가 닫히면 포커스는 시트를 연 요소(목록 행)가 아직 있으면 그리로, 없으면(마커·링크) 본문 `#main`으로 돌아간다. 시트 밖(하단 탭 등)을 눌러 닫혔으면 그 요소의 포커스를 그대로 둔다.
- 터치 영역은 44×44px 이상.

### 4.7 컴포넌트 나누기

- `src/sections/shell/PlaceSheet.tsx`: 시트 껍데기(단계·끌기·버튼·포커스). 안쪽 내용은 `children`(= `DetailSlot`). 장소 내용은 모른다.
- `src/sections/shell/sheet-snap.ts`: `resolveSnap({ from, offsetPx, velocity, halfPx, fullPx })` 순수 함수와 단계 타입.
- `src/sections/library/use-open-place.ts`: `useOpenPlace()` → `openPlace(id, from)`. compact 여부·지금 경로를 보고 push/replace와 기록 상태를 정한다.
- `AppShell`: compact 갈래에서 `DetailPane mode="sheet"`를 `PlaceSheet`로 바꾸고, 뒤 화면을 기록 상태의 `from`(없으면 지도)으로 정한다. 지금의 `origin` 상태(마지막으로 본 화면)는 기록 상태가 대신하므로 지운다. 펼치기·접기는 `navigate(지금 경로, { replace: true, state })`로 단계를 바꾼다.
- `LibraryMap`: 시트 여백·새로 생길 때 모으기. 반쯤 높이(`SHEET_HALF_MAX = 320`, `sheetHalfPx`, `useSheetHalfPx`)는 `sheet-snap.ts`에 두고 시트와 지도가 같이 쓴다.
- 시트는 첫 로딩에 들어간다(링크로 바로 들어오면 바로 보여야 하고, 크기가 작다 — 예상 gzip 2KB 안팎). 첫 로딩 예산을 넘으면 계획 단계에서 lazy로 돌린다.

## 5. 라벨 칸과 라벨 고르기 창

### 5.1 라벨 칸 (모든 크기, 상세·추가 카드 공통)

```
라벨
 ◉ 서울 맛집   ◉ 강원도 명소          ← 붙은 라벨만 (LabelBadge)
 [🏷 라벨 바꾸기]
```

- 붙은 라벨을 라벨 순서(`order`)대로 `LabelBadge`로 보인다(눌리지 않는 칩, 긴 이름은 말줄임).
- 붙은 라벨이 없으면 `붙은 라벨이 없어요`(보조 글자색).
- 아래에 `라벨 바꾸기` 버튼(`BUTTON_SX`, 라벨 아이콘). 누르면 라벨 고르기 창이 열린다. 버튼은 `aria-haspopup="dialog"`.
- 지금의 칩 목록과 `새 라벨 이름` 입력란은 창 안으로 옮긴다.
- 컴포넌트 이름과 props(`labels`, `attachedIds`, `onToggle`, `onCreate`)는 그대로 둔다. 부르는 쪽(`PlaceDetail`·`CandidateCard`·`PinCard`)은 바꾸지 않는다.

### 5.2 라벨 고르기 창

```
┌ 라벨 바꾸기 ─────────────── [완료] ┐
│ [🔍 라벨 검색 또는 새 이름      ]   │
│ ＋ ‘국밥’ 새 라벨로 붙이기          │ ← 같은 이름 라벨이 없고 검색어가 있을 때
│ ☑ ◉ 서울 맛집                 412곳 │
│ ☑ ◉ 강원도 명소                73곳 │
│ ☐ ◉ 저장 많은 TV 맛집 강원 100선 100곳│
│ ☐ ◉ 강남역 주변 맛집           94곳 │
│ …                                  │
└────────────────────────────────────┘
```

- MUI `Dialog`. compact는 화면 전체(`fullScreen`), 그 밖은 폭 420px·높이 최대 `min(640px, 80dvh)`. 제목 `라벨 바꾸기`(`aria-labelledby`), 오른쪽 위 `완료` 버튼.
- **바로 저장**: 체크할 때마다 `onToggle`을 부른다(지금 칩과 같다. 상세는 바로 저장되고, 추가 카드는 카드 안 선택만 바뀐다). `완료`·Esc·바깥 누르기는 모두 창을 닫기만 한다(취소 개념 없음). 닫으면 포커스는 `라벨 바꾸기` 버튼으로 돌아간다.
- **검색 칸**: `type="search"`, `aria-label="라벨 검색 또는 새 라벨 이름"`. 넓은·중간 화면은 창이 열리면 검색 칸에 포커스, compact는 키보드가 목록을 가리지 않도록 창(제목)에 포커스.
  - 이름에 검색어가 들어간 라벨만 남긴다(NFC·`ko-KR` 소문자로 비교, 앞뒤 공백 무시).
  - 남은 게 없으면 `‘○○’에 맞는 라벨이 없어요`.
- **새 라벨**: 검색어(앞뒤 공백 뺀 것)가 비어 있지 않고 `normalizeLabelName`이 같은 라벨이 없으면 목록 맨 위에 `＋ ‘○○’ 새 라벨로 붙이기` 버튼을 둔다. 누르거나 검색 칸에서 Enter(한글 조합 중 Enter 제외)를 치면 `onCreate(검색어)`를 부른다.
  - 같은 이름 라벨이 이미 있을 때 Enter는 그 라벨을 붙인다(`onCreate`가 지금 그렇게 한다). 이미 붙어 있으면 그대로 둔다.
  - 성공하면 검색 칸을 비운다. 새 라벨은 목록 맨 위에 체크된 채 보인다.
  - 거절 이유(이름 길이·같은 이름·장소 없음)는 검색 칸 아래 `role="alert"`로, 지금 `rejectionMessage`와 같은 문구.
- **목록**: `role="group" aria-label="라벨 목록"` 안에(보관함 필터 칩 묶음 `라벨`과 이름이 겹치지 않게) 행마다 네이티브 체크박스 + `<label>`(높이 44px 이상). 행 내용: 라벨 색·아이콘(`LabelGlyph`), 이름(말줄임, 전체 이름은 `title`이 아니라 접근 이름에 그대로 들어간다), 오른쪽에 `N곳`.
  - `N곳`: 보관함의 살아 있는 장소 중 그 라벨이 붙은 수(`labelCounts(lib, DEFAULT_QUERY)` — 지금 보관함 필터와 무관).
  - **순서**(사용자 요청 "많이 쓴 순"): 창을 연 순간 기준으로 ① 이 장소에 붙은 라벨 ② 나머지를 많이 쓴 순, 같으면 라벨 순서. 창이 열려 있는 동안은 순서를 고정한다(체크할 때마다 줄이 움직이지 않게). 창을 연 뒤 새로 만든 라벨은 맨 위.
  - 순서·거르기는 순수 함수(`orderLabelsForPicker`, `filterLabels`)로 두고 단위 시험한다.
- 라벨이 하나도 없으면 목록 대신 `만든 라벨이 없어요. 검색 칸에 이름을 쓰고 Enter로 만들어요`.
- 창은 lazy(`React.lazy`)로 불러온다. 불러오는 동안 버튼은 그대로 두고, 불러오기 실패는 지금 다른 lazy 창처럼 `ChunkErrorBoundary`가 알린다. 빌드 확인에 `--require-lazy LabelPickerDialog`를 더한다.

## 6. 시험

### 6.1 단위 (Vitest)

- `sheet-snap`: 튕기기 위/아래, 가까운 단계, 다 펼침에서 크게 끌어도 반쯤에서 멈춤, 반쯤에서 아래로 → 닫힘.
- `use-open-place`: compact에서 처음 열면 push + 상태, 이미 `/place/:id`면 replace, 넓은 화면은 push.
- `PlaceSheet`: 펼치기/접기 버튼과 `aria-expanded`, 닫기 버튼 → `onClose`, Esc → `onClose`, 열릴 때 포커스 이동, 가려진 요소에 포커스가 가면 펼침, 반쯤에서 끌기 뒤 클릭 삼키기(포인터 이벤트).
- `AppShell`(기존 compact 시험 고침): 지도에서 열면 지도가 남아 있고 시트가 반쯤, 목록에서 열면 다 펼침, 닫기 → 이전 화면, 바로 들어오면 지도 위 반쯤, 마커 두 번 → 뒤로 한 번에 `/map`, 하단 탭이 보인다.
- `LabelPicker`: 붙은 라벨만, 없을 때 문구, 버튼이 창을 연다.
- `LabelPickerDialog`: 순서(붙은 것 → 많이 쓴 순), 순서 고정, 검색 거르기, 새 라벨 행·Enter·거절 문구, 체크 → `onToggle`.
- 순수 함수 `orderLabelsForPicker`·`filterLabels`.

### 6.2 E2E (Playwright, desktop·iphone·galaxy)

- 기존 시험의 `목록으로` → `닫기`, `새 라벨 이름` 입력 → `라벨 바꾸기` 창 안 검색 칸으로 바꾼다(`library.spec.ts`·`visited-review.spec.ts`·`place-adding.spec.ts`·`trip-today.spec.ts` 등 해당 곳).
- 새 시험(@mobile): 지도에서 마커 → 시트 반쯤, 지도 마커가 여전히 보이고 다른 마커를 누르면 장소가 바뀜 → `펼치기` → `접기` → 뒤로 가기 한 번 → `/map`, 시트 없음. 새로고침해도 시트 유지.
- 새 시험(전체 크기): `라벨 바꾸기` → 검색 → 체크 → `완료` → 라벨 칸에 붙은 라벨이 보이고 새로고침 뒤에도 유지.

## 7. A1과 겹치는 곳

- `AppShell.tsx`: A1은 넓은 화면 닫기 X·중간 화면 X 돌아갈 곳·선택 해제를, A2는 compact 갈래(시트)를 고친다. 먼저 병합되는 쪽이 아니면 `main`을 받아 충돌을 풀고, **시트 내리기·닫기 = A1의 선택 해제**가 같은 함수를 쓰게 맞춘다.
- `LibraryMap.tsx`: A1은 마커 다시 누르기·지도 빈 곳 해제·필터 카메라를, A2는 `onMarkerClick`의 열기(`useOpenPlace`)와 compact 시트 여백을 고친다. 마커를 다시 누르면 해제(A1)와 바꿔치기 열기(A2)가 같은 손잡이에서 갈라지므로, 병합 때 "같은 장소면 해제, 다른 장소면 열기" 순서로 합친다.
- Esc: A1이 화면 전체 Esc 해제를 넣으면 시트의 Esc 처리는 빼고 A1 것을 쓴다(두 번 닫히지 않게).
