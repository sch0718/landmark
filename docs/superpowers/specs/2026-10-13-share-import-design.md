# 랜드마크 설계 — 받은 공유 파일 가져오기 (하위 프로젝트 C)

- 작성일: 2026-10-13
- 상태: 초안 (사용자 검토 대기)
- 관련 문서: `2026-10-11-html-share-export-design.md`(공유 파일 형식·보기 화면), `2026-10-12-place-adding-design.md`(추가 흐름·폴더 가져오기 미리보기), `2026-10-08-place-library-design.md`(§3 데이터 모델). 충돌하면 이 문서가 우선한다.

## 1. 배경과 목표

### 1.1 목표

다른 사람이 랜드마크에서 내보낸 공유 파일(HTML)을 받아, 그 장소를 **내 보관함**에 넣는다.

1. 받은 파일을 앱에서 고르거나(PC는 끌어 놓기도) 보기 화면의 `Landmark에 담기` 버튼으로 바로 연다.
2. 미리보기에서 넣을 장소를 고르고, 받은 라벨을 내 라벨과 합치거나 새로 만든다.
3. 이미 있는 장소는 새로 만들지 않고 라벨을 더하고, 원하면 받은 메모를 덧붙인다.

구글·네이버와 다른 점: 받은 목록을 그대로 복사하는 것이 아니라 **내 보관함과 합친다**. 같은 곳은 하나로 남고, 보낸 사람의 라벨과 메모가 내 장소에 붙는다.

### 1.2 사용자 결정 (2026-10-13)

| 항목 | 결정 |
|---|---|
| 들어오는 길 | **둘 다**: 앱에서 파일 고르기(＋ 시트·설정, PC는 끌어 놓기) + 보기 화면의 `Landmark에 담기` 버튼 |
| 라벨 | **보낸 사람의 라벨을 그대로 살리고**, 선택으로 **파일 제목 라벨**도 붙인다 |
| 이미 있는 장소 | 라벨을 더하고, **`받은 메모도 덧붙이기` 토글**(기본 켬)로 받은 메모를 덧붙인다 |
| 보기 화면 → 앱 | **압축한 URL 해시**(`/import#d=…`)로 넘긴다. 너무 크면 파일로 가져오라고 안내 |
| 빼는 것 | 여행 계획 가져오기(공유 파일에 여행이 없다), 받은 파일 다시 내보내기 형식 변경(형식 버전은 1 그대로) |

### 1.3 지금 있는 것

- 공유 파일: `<script type="application/json" id="tripmap-share">`에 `ShareDoc`(`src/schema/share.ts`, `format: 'tripmap-share'`, `version: 1`)이 들어 있다. 보기 화면 JS·CSS가 같은 파일에 들어 있다(`vite.viewer.config.ts`).
- 보기 화면(`src/share-viewer/*`)은 Effect를 번들에 넣지 않는다. 데이터 검사도 손으로 한다(`parse.ts`).
- 장소에는 `naverSid`만 담긴다. 카카오·구글 장소와 핀은 id가 없다.
- 압축·해독: `src/domain/codec.ts`(deflate-raw + base64url, 옛 편집 레이어용). `LIMITS`(`src/schema/common.ts`)를 import해서 Effect가 딸려 온다.
- 폴더 가져오기(`importFolder`, `FolderPreview`): 미리보기 → `LibraryStore.update` 한 번 → `summary`로 토스트 → 라벨로 목록 거르기.

## 2. 화면과 흐름

### 2.1 들어오는 길

모두 앱 주소 **`/import`** 로 모인다.

1. **＋ 추가 시트**: 새 항목 `공유 파일 가져오기`(설명 `받은 Landmark 공유 파일(.html)`). 누르면 `/import`로 간다. 여행 계획 화면에서 연 시트(여행 대상이 붙은 시트)에는 이 항목을 보이지 않는다.
2. **설정**: `옛 여행 가져오기` 옆에 `공유 파일 가져오기` 버튼. 누르면 `/import`로 간다.
3. **보기 화면의 `Landmark에 담기`**: 머리글(제목·날짜 줄 아래)에 있는 링크. 새 탭에서 `<앱 주소>/import#d=<압축 데이터>`를 연다(§4).
4. **PC 끌어 놓기**: 넓은 화면의 보관함(`/`, `/map`)에 파일을 끌어 오면 화면 전체에 `여기에 놓으면 가져와요` 덮개가 뜨고, 놓으면 그 파일을 읽는다. 파일이 여러 개면 첫 파일만 읽는다. 추가 흐름이 열려 있으면 덮개를 띄우지 않는다(`공유 파일 고르기` 칸은 그 칸 자체가 끌어 놓는 자리다).

**`/import`에 들어오면** 주소를 바로 `/`(보관함)로 바꾸고(`replace`, 해시도 지움 — 새로고침·뒤로 가기로 다시 열리지 않음) 다음을 연다.

- 해시 `#d=…`가 있으면: 해독 → 성공하면 미리보기(§2.3), 실패하면 오류 토스트(§2.5)를 띄우고 보관함에 남는다.
- 해시가 없으면: 추가 칸에 **공유 파일 고르기**(§2.2)를 연다.

### 2.2 공유 파일 고르기

추가 칸(폴더 미리보기와 같은 자리·크기)에:

- 제목 `공유 파일 가져오기`, 설명 `받은 Landmark 공유 파일(.html)을 고르면 장소를 미리 보고 내 보관함에 넣어요`.
- `파일 고르기` 버튼(`accept=".html,.htm,text/html"`). PC는 같은 칸이 끌어 놓는 자리도 된다(`여기로 끌어 놓아도 돼요`).
- 읽는 중에는 버튼을 끄고 `읽는 중…`. 실패하면 칸 안에 오류 문구(§2.5)를 보이고 다시 고를 수 있다.
- 성공하면 같은 칸이 미리보기로 바뀐다. 닫기는 추가 흐름 닫기와 같다.

### 2.3 미리보기

폴더 미리보기(`FolderPreview`)와 같은 꼴이다.

- **머리글**: `<파일 제목> · <N>곳`, 그 아래 `<YYYY.MM.DD> 만든 파일`(로컬 날짜).
- **장소 목록**: 행마다 체크박스(기본 모두 켬), 이름, 주소, 받은 라벨 칩(받은 색), 받은 메모가 있으면 `메모` 표시, 내 보관함에 같은 장소가 있으면(§3.1, 살아 있는 장소만) `이미 있음`. 위에 `모두 선택` / `모두 해제`.
- **라벨**: 고른 장소가 쓰는 받은 라벨마다 한 줄 — 색 칩, 이름, 오른쪽에 `내 라벨에 합침`(같은 이름의 살아 있는 내 라벨이 있을 때) 또는 `새로 만듦`.
- **`파일 제목 라벨도 붙이기`** 스위치(기본 켬)와 이름 입력(기본값 = 앞뒤 공백을 지운 파일 제목을 30자로 자른 것, 비면 `받은 장소`. 1–30자, 넘으면 폴더 미리보기와 같은 `라벨 이름은 30자까지예요`). 같은 이름의 내 라벨이 있으면 입력 아래 `내 라벨에 합침`.
- **`받은 메모도 덧붙이기`** 스위치(기본 켬). 설명 `이미 있는 장소에만 해당해요. 새로 넣는 장소에는 받은 메모가 그대로 들어가요`. 고른 장소 중 `이미 있음`이면서 메모가 있는 곳이 없으면 스위치를 끈 채 비활성으로 둔다.
- **버튼**: `<N>곳 가져오기`(N = 고른 수). 고른 것이 없거나 제목 라벨 이름이 잘못됐으면 꺼진다. 누르는 사이 두 번 눌러도 한 번만 한다.

`이미 있음`·`내 라벨에 합침`은 화면에 보이는 보관함 기준의 안내다. 실제 처리는 가져오기를 누른 순간의 최신본으로 다시 판단한다(§3.5).

### 2.4 가져온 뒤

- 토스트(폴더 가져오기와 같은 문장, 되살린 장소는 새로 넣은 것에 센다):
  - `<새 수>곳을 새로 넣고, <합친 수>곳은 라벨만 더했어요`
  - `<새 수>곳을 새로 넣었어요`
  - `<합친 수>곳은 라벨만 더했어요`
- 제목 라벨을 붙였으면 보관함 목록을 그 라벨로 거른다(검색어·지역·라벨 없음 필터는 비운다). 붙이지 않았으면 필터를 건드리지 않는다.
- 추가 흐름을 닫고 보관함에 남는다.

### 2.5 오류 문구

| 경우 | 문구 |
|---|---|
| 파일이 5MB(5,242,880바이트) 초과 | `파일이 너무 커요` |
| 파일에 데이터 블록(`#tripmap-share`)이 없음 | `Landmark 공유 파일이 아니에요` |
| JSON이 깨짐, 형식·버전이 다름, 스키마 불일치, 해시를 해독하지 못함 | `공유 파일을 읽지 못했어요. 파일이나 링크가 손상됐을 수 있어요` |
| 장소가 0곳 | `가져올 장소가 없는 파일이에요` |
| 장소가 1,000곳 초과 | `장소가 너무 많은 파일이에요(최대 1,000곳)` |

저장 공간 초과 등 저장소 오류는 지금처럼 앱 오류 보고자가 알린다.

## 3. 합치는 규칙

### 3.1 같은 장소 찾기

받은 장소마다 내 보관함에서 같은 장소를 찾는다. **지운 장소도 찾는다**(찾으면 되살린다).

1. **id가 있으면**(`naverSid` → `kakaoId` → `googleId` 순으로 처음 것 하나): 같은 출처·같은 id의 장소(`findExisting`과 같은 우선순위: 살아 있는 것 > 늦게 지운 것). 없으면 새로 만든다. 이름으로 다시 찾지 않는다.
   - id가 `PlaceSource` 형식(`naverSid`·`kakaoId` 숫자, `googleId` `0x…:0x…`)이 아니면 id가 없는 것으로 본다.
2. **id가 없으면**: 이름의 정규형(`normalizeLabelName`과 같은 규칙: 앞뒤 공백 제거, 연속 공백 하나로, 소문자)이 같고 직선거리(`haversineM`)가 **50m 이하**인 장소. 여럿이면 살아 있는 것 > 가까운 것 > 늦게 지운 것.
3. 찾은 장소가 지운 것이면 되살린 뒤 §3.4로 합친다.

받은 장소는 **파일 순서대로 하나씩**, 앞 장소를 처리한 결과에 이어서 처리한다. 그래서 같은 파일 안에 같은 장소가 두 번 있으면 두 번째는 첫 번째가 만든(또는 합친) 장소에 합쳐진다. 같은 id가 두 번 나오는 것도 같다.

### 3.2 새로 넣는 장소

- 받은 이름·주소·좌표·메모(10,000자 초과면 `…`로 자름).
- 출처: id 종류대로(`naver`/`kakao`/`google`), 없으면 핀(`{ kind: 'pin' }`).
- 분류(`category`)는 `null`, `saved: true`.
- 라벨: §3.3의 받은 라벨 + 제목 라벨.

### 3.3 라벨

- 대상: **고른 장소가 쓰는** 받은 라벨만. 장소의 `labelIds` 중 파일의 `labels`에 없는 id는 무시한다.
- 이름: 앞뒤 공백을 지우고 30자(UTF-16 길이, 서로게이트 쌍은 깨지 않음)로 자른다. 비면 그 라벨은 무시한다.
- 정규형이 같은 **살아 있는 내 라벨**이 있으면 그것을 쓰고(색·순서는 그대로), 없으면 받은 색으로 새로 만든다(순서는 맨 뒤). 받은 라벨 둘의 정규형이 같으면 한 라벨이 된다.
- **제목 라벨**: 같은 규칙(이름 재사용 또는 새로 만듦). 새로 만들면 색은 폴더 라벨처럼 살아 있는 라벨이 안 쓴 첫 색(모두 쓰였으면 마지막 라벨 색의 다음 색).
- 라벨을 만드는 것은 가져오기를 누른 뒤 그 연산 안에서만 한다. 미리보기만 보고 닫으면 아무것도 바뀌지 않는다.

### 3.4 이미 있는 장소에 합치기

- 라벨: 받은 라벨 + 제목 라벨을 더한다(이미 붙은 것은 그대로, 순서는 기존 라벨 뒤). 되살릴 때는 그사이 지워진 라벨을 뗀다.
- `saved: false`(여행에서만 쓰던 장소)였으면 `true`로 바꾼다.
- 메모: `받은 메모도 덧붙이기`가 켜져 있고 받은 메모가 비어 있지 않으면 아래 블록을 덧붙인다.
  ```
  — 받은 메모 (<파일 제목>):
  <받은 메모>
  ```
  - 기존 메모가 비어 있으면 블록만, 아니면 `<기존 메모>\n\n<블록>`.
  - 기존 메모가 이미 이 블록으로 끝나면 덧붙이지 않는다(같은 파일을 두 번 가져와도 한 번만).
  - 합친 길이가 10,000자를 넘으면 받은 메모 쪽을 잘라 끝에 `…`를 붙인다. 머리 줄조차 들어가지 않으면 덧붙이지 않는다.
- 이름·주소·좌표·분류는 바꾸지 않는다.

### 3.5 저장과 개수

- 가져오기는 `LibraryStore.update` 한 번(잠금 안, 최신본 기준)의 연산 `importShare`로 한다. 다른 탭이 그사이 같은 장소를 넣었으면 그 장소에 합친다.
- 개수(`summary`)는 연산이 **결과 장소 기준으로** 센다: 연산 전에 없던 장소 = `created`, 지워져 있던 장소 = `restored`, 살아 있던 장소 = `merged`. 같은 장소가 파일에 두 번 나와도 한 번만 센다.
- 토스트 개수는 미리보기가 아니라 이 `summary`에서 센다.

## 4. 보기 화면 → 앱 (`Landmark에 담기`)

- 보기 화면이 읽은 `ShareDoc`(아래 §5의 새 필드 포함)을 `JSON.stringify` → UTF-8 → `CompressionStream('deflate-raw')` → base64url(`=` 없음)로 만든다. 보기 화면은 Effect를 넣지 않으므로 이 인코더를 따로 둔다(`src/share-viewer/encode.ts`). 앱 해독기와의 왕복을 테스트로 묶는다.
- 링크 주소: `<앱 주소>/import#d=<값>`. 앱 주소는 빌드 변수 `VITE_APP_URL`, 없으면 `https://landmark-c5f.pages.dev`.
- 링크는 화면을 그릴 때 미리 만든다(누를 때 비동기로 만들면 일부 브라우저가 새 탭을 막는다). 만드는 동안과 `CompressionStream`이 없는 브라우저에서는 `<앱 주소>/import`를 가리킨다.
- 값이 **32,000자를 넘으면** 버튼 대신 `장소가 많아 바로 담을 수 없어요. Landmark에서 이 파일을 가져와 주세요` 문구와 `Landmark 열기` 링크(`<앱 주소>/import`)를 보인다.
- 링크는 `target="_blank" rel="noopener noreferrer"`. `file://`로 연 파일에서도 그대로 동작한다.

앱의 해독: 값이 32,000자를 넘거나 base64url이 아니거나, 풀린 크기가 5MB를 넘거나, 풀거나 JSON으로 읽지 못하면 §2.5의 `읽지 못했어요`. 읽은 뒤에는 파일과 같은 검사(§2.5)를 한다.

## 5. 내보내기 형식 변경

- `SharePlace`에 선택 필드 `kakaoId?: string`, `googleId?: string`를 더한다. 카카오·구글 장소를 내보낼 때 담는다. **형식 버전은 1 그대로**(새 필드는 선택이고, 옛 보기 화면은 모르는 필드를 무시한다).
- 보기 화면의 손 검사(`parse.ts`)도 두 필드를 받아 그대로 둔다(문자열이 아니면 문서 전체를 거절 — 지금의 `naverSid`와 같다). 그래야 `Landmark에 담기`로 넘길 때 빠지지 않는다.
- 이미 내보낸 파일은 그 안에 든 옛 보기 화면을 그대로 쓴다. 옛 파일에는 `Landmark에 담기`가 없으므로 앱에서 파일로 가져온다.

## 7. 테스트

- **도메인** (`import-share`): id로 찾기(살아 있는 것 우선, 지운 것 되살림), id 형식이 틀리면 이름으로, 이름+50m 이내(49m 찾음, 51m 못 찾음), 여럿이면 살아 있는 것 > 가까운 것, 파일 안 중복이 한 장소로, 라벨 재사용·새로 만듦·30자 자름·빈 이름 무시·받은 라벨 둘이 한 라벨로, 제목 라벨 켬·끔·색, 메모 블록 덧붙이기·같은 블록 건너뛰기·10,000자 자르기·머리 줄도 안 들어가면 건너뛰기·토글 끔, 새 장소 메모, `saved: false` → `true`, 이름·주소·좌표 그대로, 다른 탭이 그사이 넣은 장소에 합치고 `summary`가 그 기준, 결과가 `LibrarySchema`를 통과.
- **읽기** (`read-share`): 내보낸 HTML에서 문서 추출, 각 오류 문구의 경우(5MB 초과, 데이터 블록 없음, 깨진 JSON, 버전 2, 모르는 필드, 0곳, 1,001곳), 해시: 보기 화면 인코더 → 앱 해독 왕복(한글·이모지·`<` 포함), 32,001자·깨진 값.
- **보기 화면**: `Landmark에 담기` 링크 주소(`VITE_APP_URL` 반영, 해시 해독 시 원래 문서), 32,000자 초과 시 안내, `CompressionStream`이 없을 때 `/import`, 새 필드를 지키는 `parse`.
- **UI**: 미리보기 표시(`이미 있음`·`메모`·`내 라벨에 합침`/`새로 만듦`), 두 스위치, 모두 선택·해제, 버튼 개수·꺼짐, 토스트·필터(제목 라벨 끔이면 필터 그대로), `/import#d=` 진입 시 주소가 `/`로 바뀜, 해시 없는 진입 → 고르기 칸, 고르기 칸의 오류 문구, 여행 대상 시트에 항목 없음.
- **E2E**(desktop·iphone·galaxy): 내보내기 → 받은 파일을 `공유 파일 가져오기`로 가져오기 → 토스트·목록. 보기 화면의 `Landmark에 담기` 링크 → 앱 미리보기 → 가져오기. PC 끌어 놓기(desktop만).
- **배포 확인**: 운영 주소에서 내보낸 파일의 `Landmark에 담기` → 운영 앱 미리보기.
