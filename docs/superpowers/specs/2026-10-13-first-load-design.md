## 1. 배경과 목표

### 1.1 지금 (2026-10-13, main `15adf03`)

- 앱 JS가 파일 하나다: 1,205,096바이트, gzip 약 385KB. 첫 화면(보관함·지도)에 필요 없는 코드도 처음에 모두 받는다.
- 구성(압축 전, source map으로 어림): react-dom·react·react-router 약 300KB, MUI 약 215KB, Effect 약 110KB, 여행 계획 화면 + @dnd-kit 약 155KB, 장소 추가 칸 약 31KB, 설정 약 22KB, 라벨 관리 약 19KB, 공유 파일 미리보기 약 16KB, 그 밖(sonner·jotai·목록 가상화 등) 약 90KB.
- 과거 PoC의 다운로드 예산(첫 화면 JS gzip 276,873바이트 + 15%·50KiB 이내)은 지금 앱 크기에 맞지 않는다.

| 항목 | 결정 |
|---|---|
| 방식 | 화면별 나눠 받기 + 라이브러리 묶음 분리 + 크기 예산 검사 |
| 목표 | 숫자 목표 대신 **이번에 줄인 값을 새 기준**으로 삼고, 첫 화면 JS가 그 기준보다 **10% 넘게 늘면 실패** |

### 1.3 목표

1. 첫 화면에서 받는 JS를 줄인다(나눠 받기 전후를 재서 기록).
2. 나눠 받은 화면으로 넘어갈 때 기다림이 거의 없게 한다(미리 받기).
3. 새 배포 뒤 옛 파일이 없어도 깨진 화면 대신 안내를 보인다.
4. 다시 커지면 CI가 알린다.

## 2. 나눠 받을 것

"첫 화면"은 보관함(`/`), 지도(`/map`), 장소 상세(`/place/:id`)다. 이 셋과 셸(메뉴·추가 시트·저장 배너·끌어 놓기 덮개·`/import` 진입 훅)은 처음에 받는다.

| 단위 | 받는 때 |
|---|---|
| 여행 목록(`/trips`)·여행 계획(`/trips/:id`) | 그 화면에 들어갈 때 |
| 설정(`/settings`) | 〃 |
| 라벨 관리(`/labels`) | 〃 |
| 옛 여행 가져오기(`/t/:publicId`) | 〃 |
| 추가 칸의 단계 화면: 링크 입력, 확인 카드, 폴더 미리보기, 핀 카드, 공유 파일 고르기, 공유 미리보기 | 그 단계가 열릴 때 |
| 공유 내보내기 대화상자(`ExportHtmlDialog`) | 대화상자를 열 때 |

- 핀 찍기 덮개(`pin` 단계)는 지도 위에 바로 떠야 하므로 처음에 받는다.
- 보관함 화면이 직접 쓰는 여행 기능(`여행에 넣기`, `이 지역으로 여행 만들기`, 추가 흐름의 여행 대상)은 첫 화면에 남을 수 있다. 구현할 때 실제로 갈린 경계를 재서 §6 기록에 적는다. 이 경계를 맞추려고 기능을 바꾸지 않는다.
- 라우트 화면·추가 칸 단계·대화상자 모두 `React.lazy` + `Suspense`로 나눈다. 라우트는 react-router의 `lazy`를 쓰지 않는다: 주소를 직접 열거나 새로고침하면 `lazy`가 끝날 때까지 셸까지 그리지 않아 빈 화면이 되기 때문이다. `Suspense`를 라우트 화면 자리에 두면 셸은 바로 그려지고 그 자리에만 기다림 표시가 뜬다(직접 진입·앱 안 이동 모두). 기다리는 동안은 지금 셸이 쓰는 `불러오는 중…`(`role="status"`)을 같은 모양으로 보인다.
- 공유 내보내기 대화상자는 **처음 열 때 받고, 그 뒤로는 계속 마운트해 둔다**(열고 닫기는 지금처럼 `open`으로). 이 대화상자는 `open`이 `false`로 바뀔 때 진행 중인 저장을 무효화하므로, 닫을 때 마운트를 지우면 닫은 창의 저장이 이어진다.

## 3. 라이브러리 묶음

첫 화면 JS를 세 덩어리로 따로 묶는다: **react**(react, react-dom, react-router, scheduler), **mui**(@mui/*, @emotion/*), **effect**(effect). 앱 코드만 바뀐 배포 뒤 다시 방문하면 이 셋은 파일 이름(해시)이 그대로라 캐시를 쓴다. 다른 라이브러리는 쓰는 쪽 묶음에 둔다(@dnd-kit은 여행 계획 쪽). Vite 8(rolldown)의 청크 묶음 설정으로 하며, 첫 화면에서 받는 파일 수가 4~6개를 넘지 않게 한다.

## 4. 미리 받기

첫 화면을 그린 뒤 브라우저가 한가할 때(`requestIdleCallback`, 없으면 `setTimeout` 2초) §2의 단위들을 미리 받는다(같은 `import()` 함수를 불러 결과는 버린다).

- 한 번만 한다. 실패는 조용히 무시한다(실제로 그 화면에 갈 때 §5가 처리한다).
- 데이터 절약 모드(`navigator.connection.saveData === true`)면 미리 받지 않는다.
- 테스트(Vitest)에서는 예약 함수를 바꿔 끼울 수 있게 한다.

## 5. 새 배포 뒤 옛 파일이 없을 때

앱을 열어 둔 채 새 버전이 배포되면 나중에 받으려던 옛 파일이 404일 수 있다. 나눠 받는 `import()`가 실패하면:

- **화면(라우트)**: 라우트 오류 화면 자리에 `새 버전이 나왔어요. 새로고침해 주세요` 문구와 `새로고침` 버튼(누르면 `location.reload()`)을 보인다. 다른 라우트 오류는 지금의 `문제가 생겨 화면을 표시하지 못했어요` 화면 그대로.
- **추가 칸 단계·내보내기 대화상자**: 그 칸(대화상자) 안에 같은 문구와 `새로고침` 버튼을 보인다. 칸 닫기는 그대로 된다.
- 받기 실패의 판정: 나눠 받기를 감싼 함수(`lazyChunk`)가 `import()`의 실패를 `ChunkLoadError`로 바꿔 던진다. 오류 화면은 이 종류일 때만 새 버전 안내를 고른다.
- 자동 새로고침은 하지 않는다(입력 중인 내용을 잃을 수 있다).

새 문구는 `새 버전이 나왔어요. 새로고침해 주세요` 하나뿐이다(`새로고침`은 기존 버튼 문구).

## 6. 크기 예산과 기록

- `scripts/check-bundle-size.mjs`(`yarn size`): 빌드 결과 `dist/index.html`이 처음에 받는 JS — `<script type="module" src>`와 `<link rel="modulepreload" href>` — 각각의 gzip 바이트와 합(**첫 화면 JS**), 그리고 `dist/assets`의 모든 JS gzip 합(**전체 JS**)을 출력한다. `perf-budget.json`의 `initialJsGzipMax`보다 첫 화면 JS가 크면 종료 코드 1.
- `perf-budget.json`: `{ "initialJsGzipMax": <나눠 받은 뒤 잰 첫 화면 JS × 1.10, 1KB 단위 올림>, "measuredAt": "<YYYY-MM-DD>", "measuredInitialJsGzip": <잰 값> }`.
- `build:ci`에서 `build` 다음에 `size`를 돌린다(CI도 함께).
- `docs/ui-performance.md`에 `2026-10-13 D2 첫 로딩` 절: 전후 첫 화면 JS·전체 JS(원본·gzip), 첫 화면 파일 목록, 첫 화면에 남은 여행 기능 경계(§2), 측정 명령.
- 예산을 올려야 할 때는 `perf-budget.json`을 고치고 그 이유를 이 절에 적는다(자동으로 올리지 않는다).

## 7. 테스트

- **단위**: `lazyChunk` — 성공하면 모듈, 실패하면 `ChunkLoadError`. 미리 받기 — 한가할 때 한 번만, `saveData`면 안 함, 실패를 삼킴. 오류 화면 — `ChunkLoadError`면 새 버전 안내와 `새로고침`, 다른 오류면 기존 문구. 추가 칸 — 단계 받기 실패 시 칸 안 안내, 닫기 동작.
- **크기 스크립트**: 작은 가짜 `dist`(진입 + modulepreload 2개 + 나중 파일 1개)로 첫 화면·전체 합과, 상한 초과 시 종료 코드 1.
- **E2E**: 기존 전체 통과(나눠 받은 화면의 흐름 포함). 첫 화면을 연 뒤 `/trips`·`/settings`·`/labels` 이동이 된다. `/trips`를 주소로 바로 열어도 셸이 먼저 그려진다. 나중에 받는 모듈 요청을 `page.route`로 404로 만들고 그 화면으로 가면 새 버전 안내가 뜬다(E2E 앱은 Vite 개발 서버라 모듈 주소가 `/src/sections/trips/TripsPage.tsx`이다. 차단이 실제로 일어났는지 횟수로 확인한다). 내보내기 대화상자: 저장 중 닫았다 다시 열어도 이전 저장이 내려받기·닫기를 하지 않는다.
- **빌드**: `yarn build:ci` 통과(`yarn size` 포함). 실제 빌드에서 `yarn size`가 보고한 첫 화면 파일 목록에 여행 계획·설정·라벨·옛 여행 가져오기 화면의 파일이 없다(빌드 설정에서 나눠 받는 파일 이름에 화면 이름이 드러나게 하고, 스크립트가 `--forbid <이름>`을 받아 첫 화면 목록에 있으면 실패한다).
