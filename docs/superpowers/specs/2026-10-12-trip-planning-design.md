# 랜드마크 설계 — 여행 계획 (하위 프로젝트 3)

- 작성일: 2026-10-12
- 상태: 초안 (사용자 검토 대기)
- 관련 문서: `2026-10-08-place-library-design.md`(하위 프로젝트 1, §2.1 하위 프로젝트 목록·§3 데이터 모델), `2026-10-12-place-adding-design.md`(하위 프로젝트 2, 서버 함수 구조). 이 문서는 하위 프로젝트 1 문서의 3번을 구체화한다. 충돌하면 이 문서가 우선한다.

## 1. 배경과 목표

### 1.1 목표

보관함에 모은 장소로 여행 일정을 짠다.

1. 지역·라벨로 **후보**를 추려 여행에 담는다.
2. 후보를 **Day**에 넣고 순서를 정한다. 넣기는 한 번의 행동이다.
3. 구간마다 **자동차·도보 경로와 시간**을 바로 계산하고, 장소별 **도착 시각**을 보여 준다.
4. **순서 정리**(그날 동선을 짧게)와 **Day 자동 나누기**(후보를 날짜별로 묶기)를 버튼 하나로 한다.

구글·네이버 지도와 다른 점: 내가 저장한 장소·메모가 중심이고, "갈까 말까 한 곳"을 후보로 모아 두고 고르며, 일정 시각과 예약 시각의 여유·늦음을 바로 보여 준다.

### 1.2 사용자 결정 (2026-10-12)

| 항목 | 결정 |
|---|---|
| Day 배치 | **직접 배치가 기본**, Day 안 순서는 `순서 정리` 버튼으로 자동. **Day 자동 나누기**는 별도 기능(미리보기 후 적용) |
| 출발·도착 | **Day마다 숙소 지정**(그날 밤 숙소 = 다음 날 출발지). 숙소가 없으면 **첫 장소 = 출발, 마지막 장소 = 도착** |
| 이동 수단 | **거리로 자동**(직선 800m 이하 도보, 그 밖 자동차) + **구간별로 사람이 바꾸면 그 값이 우선** |
| 시간 | **Day 시작 시각 + 체류 시간으로 도착 시각 자동 계산**, 예약 등 **고정 시각**은 늦음·여유 표시 |
| 후보 | **여행마다 후보 목록**. 여행을 만들 때 지역·라벨로 담고, 나중에 더할 수 있음 |
| 순서 계산 | **직선거리로 순서를 정하고**, 확정된 구간만 실제 경로로 계산 |
| PC 화면 | **왼쪽 후보 · 가운데 지도 · 오른쪽 Day 시간표**. 장소 정보는 **지도 위 카드**, 전체 상세는 카드의 `상세`로 오른쪽 칸 |
| 휴대폰 화면 | **지도 + 아래에서 끌어올리는 시트**(시트 안 탭: 후보 / Day 1 / Day 2 …) |
| 빼는 것 | 여행 공유·내보내기(하위 프로젝트 4), 대중교통, 영업시간 확인 |

### 1.3 확인된 사실 (2026-10-12, 개발 PC에서 `curl`)

| 대상 | 결과 |
|---|---|
| 자동차 `map.naver.com/p/api/directions/car?start=경도,위도&goal=경도,위도` (`Referer: https://map.naver.com/`, 브라우저 UA) | 200. `route.<옵션키>[0]`에 `summary{distance(m), duration(ms), staticDuration(ms), tollFare, fuelPrice, taxiFare}`, `path[[경도,위도]…]`. `waypoints=`를 넣으면 `summary.waypoints[]`에 구간별 거리·시간 |
| 도보 `map.naver.com/p/api/directions/walk?o=all&l=경도,위도;경도,위도&lang=ko` | 200. `routes[0].summary{distance(m), duration(**초**)}`, `routes[0].legs[0].steps[].path`(`"경도,위도 경도,위도 …"` 문자열, 첫 단계는 `null`). `o`·`l`이 없으면 400 |
| 도보 다른 경로(`walking`, `pedestrian`) | 404 |
| 응답 `code` | 자동차·도보 모두 본문에 `code`가 있다. 성공은 `0`(자동차 `"길찾기를 성공하였습니다."`, 서울→제주도 `0`). 도보는 직선거리 50km 초과면 **HTTP 200**에 `{"code":4,"error":"출발지와 도착지 간의 직선거리가 50km 이내인 경우만 도보 길찾기를 제공합니다."}` |

자동차 시간은 밀리초, 도보 시간은 초다. Cloudflare 서버에서의 동작은 구현 중 미리보기 배포에서 확인한다(§7).

## 2. 화면과 흐름

### 2.1 여행 목록 (`/trips`, 왼쪽 메뉴 "여행")

- 지금의 `TripsPlaceholder`를 바꾼다. 여행 카드: 제목, 기간(`10.24(금) ~ 10.26(일) · 2박 3일`), Day에 넣은 장소 수·후보 수. 시작일이 가까운 순, 지난 여행은 아래 "지난 여행"으로.
- `새 여행` → 대화상자: 제목(필수, 1–60자), 시작일·종료일(필수, 최대 30일), 1일차 출발지(선택, §2.4의 장소 고르기). 만들면 `/trips/:id`로 간다.
- 카드 메뉴: 이름 바꾸기, 삭제(확인 후 묘비, 토스트 `되돌리기`).

### 2.2 후보 넣는 길

모두 한 번의 행동으로 끝난다.

1. **보관함 지역 칩**(예: `강릉 31`)을 **하나만** 고르면 칩 줄 끝에 `이 지역으로 여행 만들기`가 나온다. 누르면 새 여행 대화상자가 제목 `강릉 여행`으로 채워져 열리고, 만들면 그 지역의 보관함 장소(다른 검색·라벨 필터와 상관없이 그 지역의 살아 있는 보관함 장소 전부)가 후보가 된다.
2. **보관함에서 여러 장소 선택** → 일괄 편집 바 `여행에 넣기` → 여행 고르기(또는 `새 여행`) → 후보에 더한다.
3. **계획 화면의 `보관함에서 더하기`** → 지역·라벨·검색으로 거른 보관함 목록에서 체크해 더한다.
4. **장소 추가 흐름**(하위 프로젝트 2)을 계획 화면의 `링크·핀으로 새로 추가`로 열면 흐름에 "이 여행" 대상이 붙는다. 확인 카드·핀 카드에 `보관함에도 저장`(기본 켬) 선택이 생기고, 끄면 `saved: false`(보관함 목록에서 숨김)로 만든다(폴더 가져오기는 폴더 라벨이 붙으므로 늘 보관함에 저장). 추가가 끝나면 그 장소(폴더면 가져온 장소들)를 이 여행의 후보에 더하고 `/trips/:id`로 돌아온다. 흐름 중 지도는 하위 프로젝트 2처럼 보관함 지도를 쓴다.

이미 그 여행에 있는 장소(후보 또는 Day)는 다시 넣지 않고 `이미 Day 2에 있어요` / `이미 후보에 있어요`로 알린다. 여러 곳을 한꺼번에 넣을 때는 새로 넣은 수만 `5곳을 후보에 넣었어요`로 알린다.

### 2.3 계획 화면 (`/trips/:id`)

**PC(넓은 화면)**: 왼쪽 메뉴 레일 · 후보 칸(목록 칸 자리) · 지도 · Day 시간표 칸(상세 칸 자리, `DETAIL_WIDTH`).

- **후보 칸**: 머리에 여행 제목·기간, `후보 N`. 장소 행마다 이름·지역·대표 라벨 색, 오른쪽 `＋`(지금 보는 Day에 넣기). 아래 `보관함에서 더하기`, `링크·핀으로 새로 추가`, `Day 자동 나누기`.
- **지도**: 지금 Day의 장소는 번호 핀(1, 2, 3 …)과 경로선(도보 구간은 점선), 출발지·숙소는 집·침대 아이콘 핀, 후보는 회색 핀, 다른 Day 장소는 흐린 작은 점. 핀은 묶지 않는다(클러스터 없음).
- **지도 위 카드**(장소 핀·후보 행·시간표 행을 누르면): 이름, 분류, 위치(`후보` / `Day 2 · 3번째`), 버튼 — 후보면 `Day N에 넣기`, Day 장소면 체류 시간(분)·고정 시각 입력, `다른 Day로` 메뉴, `후보로 빼기`; 공통 `숙소로 정하기`(그 Day의 숙소), `상세`(오른쪽 칸에 기존 장소 상세, `← 일정으로`로 돌아옴).
- **Day 시간표 칸**: 위에 Day 탭(`Day 1 10.24(금)` …). 머리: 출발 시각(기본 09:00, 눌러 바꿈), 출발지(전날 숙소 또는 여행 출발지 또는 첫 장소), `순서 정리`. 몸통: 장소 행(번호, 도착 시각, 이름, 체류 시간, 고정 시각이면 자물쇠와 `여유 40분`/`늦음 15분`)과 구간 행(수단 아이콘·시간·거리, 눌러 수단 바꾸기, `네이버 지도로 길찾기`). 꼬리: 숙소(없으면 `숙소 정하기`), 그날 합계(이동 시간·거리·통행료), `10월 12일 조회 · 다시 계산`.
- **끌어 옮기기**: 시간표 안에서 순서 바꾸기, 후보 행을 시간표의 자리로 끌어 그 자리에 넣기, 시간표 행을 후보 칸으로 끌어 빼기, Day 탭 위로 끌어 다른 Day로 옮기기. 키보드로도 같은 일을 할 수 있다(행 메뉴의 `위로`·`아래로`·`다른 Day로`·`후보로 빼기`).
- **중간 폭**: 후보 칸을 접을 수 있고(레일의 후보 버튼으로 다시 엶), 시간표 칸은 지도 위에 덮인다.

**휴대폰(좁은 화면)**: 지도를 화면 전체에, 아래에 끌어올리는 시트(접힘: 탭 줄만 / 반쯤 / 거의 전체). 시트 탭: `후보 N`, `Day 1`, `Day 2` …. 내용은 PC의 후보 칸·시간표 칸과 같다. 지도 핀이나 행을 누르면 시트를 접고 지도 위 카드를 띄운다. 기존 아래 메뉴는 계획 화면에서도 그대로 둔다.

### 2.4 출발지·숙소 고르기

출발지(`origin`)와 숙소(`lodging`)는 보관함의 장소다(`saved: false` 장소 포함). 고르기 창: 이 여행의 장소 + 보관함 검색(이름·주소). 보관함에 없는 곳은 먼저 §2.2의 `링크·핀으로 새로 추가`로 후보에 넣은 뒤 고른다. 숙소는 Day 시간표 꼬리의 `숙소 정하기`, 지도 위 카드의 `숙소로 정하기`로 정하고, 고르기 창의 `다음 날들도 같은 숙소`(기본 끔)를 켜면 그 뒤 Day들의 숙소도 같은 곳으로 바꾼다.

### 2.5 순서 정리 · Day 자동 나누기 · 되돌리기

- `순서 정리`: §5.1로 지금 Day의 순서를 바꾸고 `순서를 정리했어요` + `되돌리기`. 이미 가장 짧으면 바꾸지 않고 `이미 가장 짧은 순서예요`.
- `Day 자동 나누기`: 후보가 1곳 이상이고 Day가 있을 때 켜진다. §5.2 결과를 **미리보기**로 보인다 — 지도에 Day별 색으로 묶음, 칸에 `Day 1에 4곳, Day 2에 3곳 …`. `적용` → 반영 + `되돌리기` 토스트, `취소` → 그대로.
- **되돌리기**: 순서 정리, 자동 나누기 적용, 장소 넣기·빼기·옮기기, 날짜 변경은 토스트 `되돌리기`(8초)로 바로 전 상태로 돌린다. 되돌리기는 그 연산 직전의 `trip` 값으로 다시 쓰는 연산이다(다른 탭이 그사이 바꾼 필드는 LWW로 다룬다).

### 2.6 여행 설정

시간표 칸 머리의 `여행 설정`: 제목, 기간, 출발지. 기간을 줄여 사라지는 Day에 장소가 있으면 먼저 `Day 3의 4곳은 후보로 돌아가요. 바꿀까요?`로 확인한다. 기간을 늘리면 빈 Day가 뒤에 생긴다. 시작일만 옮기면(같은 날 수) Day 내용은 그대로 날짜만 바뀐다.

## 3. 데이터

### 3.1 저장 형식

`src/schema/library.ts`의 `trips`(지금은 빈 객체만 허용)를 정의한다. `schemaVersion`은 **2 그대로**, 저장 키(`tripmap:library:v2`)도 그대로다.

```
Trip
  id          TripId                        # 영숫자 소문자 10자
  title       Field<string>                 # 1–60자
  startDate   Field<CalendarDate>           # 'YYYY-MM-DD'
  endDate     Field<CalendarDate>           # startDate ≤ endDate, 최대 30일
  origin      Field<PlaceId | null>         # 1일차 출발지
  candidates  Field<PlaceId[]>              # 후보(순서 있음)
  days        Day[]                         # 길이 = 날짜 수
  legModes    Field<Record<LegKey, 'car' | 'walk'>>   # 사람이 바꾼 구간만. LegKey = "<출발 PlaceId>><도착 PlaceId>"
  createdAt   IsoDateTime
  deletedAt   IsoDateTime | null

Day
  stops       Field<Stop[]>
  lodging     Field<PlaceId | null>         # 그날 밤 숙소(마지막 날은 도착지)
  startTime   Field<HHmm>                   # 기본 '09:00'

Stop
  id          StopId                        # 영숫자 소문자 8자, 여행 안에서 유일
  placeId     PlaceId
  stayMin     number | null                 # 0–1440 정수
  fixedTime   HHmm | null
  note        string                        # 최대 500자
```

**검증 규칙**(스키마에서 거부):
- `days.length`는 `startDate`~`endDate`의 날 수와 같다.
- 한 여행 안에서 장소 하나는 `candidates`와 모든 Day의 `stops`를 통틀어 **한 번만** 나온다. `origin`·`lodging`은 이 규칙 밖이다(숙소 카페를 낮에 들를 수 있다).
- 참조하는 `PlaceId`는 `places`에 있어야 한다(묘비인 장소도 허용 — §3.3).
- `StopId`는 여행 안에서 유일하다.

### 3.2 출발·도착과 구간

Day `d`(0부터)의 **출발점**은 `d = 0`이면 `origin`, 아니면 `days[d-1].lodging`이다. **도착점**은 `days[d].lodging`이다. 출발점이 없으면 첫 장소에서 출발하고, 도착점이 없으면 마지막 장소에서 끝난다. 그날 구간은 `[출발점?, stop1, …, stopN, 도착점?]`의 이웃한 쌍이다. 장소가 0곳이고 출발점·도착점이 모두 있으면 구간 하나(출발점 → 도착점)다.

**구간의 이동 수단**: `legModes["from>to"]`가 있으면 그 값, 없으면 직선거리 **800m 이하면 도보, 아니면 자동차**. 사람이 수단을 바꾸면 `legModes`에 기록하고, 자동 값과 같은 쪽으로 되돌리면 그 항목을 지운다. 직선거리 50km를 넘는 구간은 도보를 고를 수 없다(네이버 도보 길찾기 한도).

### 3.3 장소 삭제와의 관계

보관함에서 장소를 지우면(묘비) 여행의 참조는 그대로 두고 **화면과 계산에서 뺀다**(Day에서는 그 장소를 건너뛰어 앞뒤 장소를 잇는다). 보관함에서 되살리면 원래 자리로 돌아온다. 계획 화면을 열 때 숨겨진 장소가 있으면 `보관함에서 지운 2곳은 일정에서 빠졌어요`를 한 번 보인다. 묘비 정리(하위 프로젝트 4)에서 참조를 함께 지운다.

### 3.4 도메인 연산 (`src/domain/trips/ops.ts`)

모두 `(lib, …, ctx) => OpResult`(기존 `useLibraryAction().run` 경로, 잠금 안에서 최신본에 적용). 바뀐 필드만 `updatedAt`을 갱신한다.

`createTrip`(제목·기간·출발지·처음 후보), `renameTrip`, `setTripDates`(줄일 때 사라지는 Day의 장소를 후보 끝으로), `setOrigin`, `deleteTrip`/`restoreTrip`, `addCandidates`(이미 있는 장소는 건너뛰고 `summary`로 새로 넣은 수), `removeCandidate`, `insertStop`(후보 또는 다른 Day에서 지정한 Day·자리로), `moveStop`, `unscheduleStop`(후보로), `setStopStay`, `setStopFixedTime`, `setStopNote`, `setLodging`(선택: 이후 Day들에도), `setDayStartTime`, `setLegMode`, `reorderDay`(순서 정리 결과), `applyAutoSplit`(미리보기 결과), `replaceTrip`(되돌리기).

### 3.5 경로 결과 저장 (문서 밖)

키 `tripmap:routes:v1`. 값: `{ entries: Record<RouteKey, RouteEntry> }`, `RouteKey = "<mode>:<경도>,<위도>><경도>,<위도>"`(좌표는 소수 5자리로 반올림). `RouteEntry = { distanceM, durationS, tollFare | null, path: [경도, 위도][], queriedAt, usedAt }`. 500개를 넘으면 `usedAt`이 오래된 것부터 지운다. 내보내지 않고, 기기마다 따로다. 저장이 꽉 차면(쿼터) 가장 오래된 절반을 지우고 한 번 더 시도하고, 그래도 안 되면 메모리에만 둔다.

## 4. 경로 계산

### 4.1 서버 함수 `GET /api/route`

하위 프로젝트 2의 구조(`functions/api/*.ts` + `src/server/*`, 상대 경로 import만)를 따른다.

- 질의: `mode=car|walk`, `from=경도,위도`, `to=경도,위도`. 좌표는 한국 범위(경도 124–132, 위도 33–39)만 받는다. 아니면 `400 BAD_REQUEST`.
- 출처 검사·오류 본문 형식·8초 시한·`map.naver.com`만 허용하는 요청기·https 고정은 하위 프로젝트 2의 것을 쓴다. 허용 출처도 같다.
- 자동차: `directions/car?start=from&goal=to` → `distance`, `duration`(ms → 초로 반올림), `tollFare`, `path`.
- 도보: `directions/walk?o=all&l=from;to&lang=ko` → `distance`, `duration`(초), `legs[0].steps[].path` 문자열을 이어 붙인 점들. 통행료 `null`.
- 경로선은 Douglas–Peucker로 **200점 이하**로 줄인다(처음·끝 점 유지).
- 응답 `200 { mode, distanceM, durationS, tollFare, path, queriedAt }`.
- 본문 `code`가 `0`이 아니거나 경로가 비면(자동차 `route`에 결과 없음, 도보 `routes` 빈 배열) `404 NO_ROUTE`(HTTP 상태가 200이어도 `code`로 판단한다). 응답이 JSON이 아니거나 네이버가 4xx·5xx면 `502 UPSTREAM_ERROR`, 시한 초과는 `504 TIMEOUT`.
- 도보는 직선거리 **50km 초과**면 네이버에 묻지 않고 바로 `NO_ROUTE`다.
- 엣지 캐시: 키는 질의를 정규화한 값(좌표 소수 5자리), 자동차 1시간·도보 7일. 브라우저에는 `private, no-store`(하위 프로젝트 2와 같다).

### 4.2 앱의 경로 서비스 (`src/services/route-lookup.ts`)

- `RouteLookup.leg(mode, from, to)`: 문서 밖 캐시(§3.5) → 없으면 서버. 같은 키 요청이 진행 중이면 하나로 합친다. 동시 요청은 4개까지.
- 계획 화면은 **지금 보는 Day의 구간을 먼저**, 나머지 Day는 그다음 차례로 요청한다.
- 결과가 없거나 실패한 구간은 **직선 추정**으로 시간을 계산한다(자동차 시속 40km, 도보 시속 4km, 직선거리 × 1.3). 표시는 `직선 추정`(회색) 또는 `경로 없음 · 직선 추정`.
- `다시 계산`: 그 Day의 구간을 캐시를 건너뛰고 다시 요청한다.
- 시간 기준: 자동차는 네이버가 준 `duration`(조회 시점 교통 반영). 시간표 꼬리에 가장 오래된 `queriedAt`의 날짜를 `10월 12일 조회`로 보인다.

### 4.3 시각 계산 (`src/domain/trips/schedule.ts`, 순수 함수)

`출발 = startTime`. 장소마다 `도착 = 앞 출발 + 구간 시간`, 고정 시각이 있으면 `여유 = 고정 - 도착`(양수면 기다림, 그 장소의 출발은 `고정 + 체류`), 음수면 `늦음`(출발은 `도착 + 체류`). 체류 시간이 비면 0분. 하루를 넘기면 `다음 날 01:10`처럼 보인다. 그날 합계: 이동 시간·거리·통행료(알려진 값만 더하고, 추정이 섞이면 `약`).

## 5. 순서 정리와 자동 나누기 (`src/domain/trips/optimize.ts`, 순수 함수)

거리는 **직선거리(하버사인)**로 계산한다.

### 5.1 순서 정리

- 입력: 출발점(없으면 지금 첫 장소를 출발로 고정), 도착점(없으면 끝은 자유), 장소들, 고정 시각들.
- **제약**: 고정 시각이 있는 장소끼리는 시각이 이른 것이 먼저 온다.
- 움직일 장소가 **12곳 이하**면 Held–Karp(비트 DP)로 최단을 정확히 구한다. 제약을 어기는 상태는 건너뛴다. 13곳 이상이면 가까운 곳 먼저(nearest neighbor)로 시작해 2-opt로 개선한다(제약을 어기는 교환은 하지 않는다).
- 결과 총 거리가 지금보다 **1% 이상 짧을 때만** 바꾼다.

### 5.2 Day 자동 나누기

- 입력: 후보들, Day들(각 Day의 출발점·도착점·이미 넣은 장소).
- **기준점**: Day마다 출발점·도착점·이미 넣은 장소의 좌표 평균. 기준점이 하나도 없는 Day가 있으면, 그 Day들의 기준점은 후보 좌표로 k-means++ 초기화 → k-means(최대 50회)로 정한다.
- **배정**: 각 Day의 용량 = `ceil((후보 수 + 이미 넣은 장소 수) / Day 수) - 이미 넣은 장소 수`(0 미만은 0). 모든 (후보, Day) 쌍을 기준점까지 거리순으로 보며 용량이 남은 Day에 배정한다. 용량이 모두 차서 남은 후보는 가장 가까운 Day에 넣는다.
- 배정된 장소를 그 Day 끝에 붙인 뒤 Day마다 §5.1을 적용한 결과가 미리보기다. 이미 넣은 장소의 상대 순서는 §5.1이 바꿀 수 있다(미리보기에 보인다).

## 6. 오류와 문구

| 상황 | 문구 / 동작 |
|---|---|
| 구간 경로 없음(`NO_ROUTE`) | 구간에 `경로 없음 · 직선 추정` |
| `UPSTREAM_ERROR`·`TIMEOUT` | 구간에 `경로를 못 가져왔어요` + `다시 시도`, 시간은 직선 추정 |
| 오프라인(`OFFLINE`) | 캐시 사용, 없으면 직선 추정. 계획 화면 위에 한 번 `인터넷에 연결되지 않아 이동 시간은 어림값이에요` |
| 이미 여행에 있는 장소 | `이미 Day 2에 있어요` / `이미 후보에 있어요` |
| 기간 줄이기 | `Day 3의 4곳은 후보로 돌아가요. 바꿀까요?` |
| 기간 31일 이상 | `여행은 30일까지 만들 수 있어요` |
| 제목 비었음 / 61자 이상 | `여행 이름을 넣어 주세요` / `여행 이름은 60자까지예요` |
| 순서 정리 결과 같음 | `이미 가장 짧은 순서예요` |
| 지운 장소 숨김 | `보관함에서 지운 N곳은 일정에서 빠졌어요` |
| 없는 여행(`/trips/:id`) | `여행을 찾지 못했어요` + `여행 목록으로` |

## 7. 테스트

- **도메인 단위**: 연산마다 불변식(장소 한 번만, Day 수 = 날짜 수, 줄일 때 후보로 복귀), `legModes` 기록·삭제, 되돌리기.
- **순서 정리**: 7곳 이하 무작위 입력에서 모든 순열을 따진 답과 같은 길이, 고정 시각 순서, 출발·도착 고정, 출발 없음(첫 장소 고정)·도착 없음, 13곳 이상 근사 경로가 제약을 지킴, 1% 기준.
- **자동 나누기**: 용량 균형(최대·최소 차 1 이하, 넘침 제외), 숙소 기준점 배정, 기준점 없는 Day의 k-means, 결정적 결과(같은 입력 → 같은 결과).
- **시각 계산**: 여유·늦음, 체류 비움, 자정 넘김, 추정 섞인 합계.
- **이동 수단 자동**: 800m 경계, 사람 값 우선, 자동 값으로 되돌리면 항목 삭제.
- **스키마**: 위 검증 규칙 위반 거부, 묘비 장소 참조 허용.
- **서버**: 녹화한 자동차·도보 응답(단위 차이 ms/초), 경로선 줄이기(200점, 끝점 유지), HTTP 200 + `code: 4` 도보 응답 → `NO_ROUTE`, 50km 초과 도보는 네이버에 묻지 않음, `UPSTREAM_ERROR`·`TIMEOUT`·범위 밖 좌표·출처 검사, 캐시 키 정규화.
- **경로 서비스**: 캐시 적중·합치기·동시 4개·LRU 500·쿼터 초과 처리·직선 추정 대체.
- **화면**: 후보 `＋`로 넣기, 지도 카드 `Day N에 넣기`, 끌어 넣기·빼기·옮기기(키보드 메뉴 포함), 순서 정리·되돌리기, 자동 나누기 미리보기·적용·취소, 기간 줄이기 확인, 숙소 정하기, 지운 장소 안내.
- **E2E**(desktop·iphone·galaxy, `/api/route`는 녹화 응답): `@smoke 지역 칩으로 여행을 만들고 Day에 넣으면 시간표가 나온다`, `순서 정리`, `Day 자동 나누기`.
- **배포 확인(직접)**: 미리보기 배포의 `/api/route`로 자동차·도보 각각 실제 응답(거리·시간·경로선 점 수)을 확인하고 보고한다. 도보는 Cloudflare 서버에서 처음 확인하는 것이므로, 실패하면 원인과 대안(도보는 직선 추정만)을 보고한다.
